## 이 부록의 자리

이 부록은 **성취기준에 배정된 차시가 아니다.** 「프로그래밍」 성취기준 14개에 GUI를 다루라는 항목은 없다. 그래서 정식 차시로 두지 않고 부록에 담았다.

그럼에도 실을 값이 있는 까닭은 두 가지다. 첫째, **입력과 출력의 또 다른 모습**이다 — 2단원 5·6차시의 「받아서 처리하고 보여 준다」가 창과 단추로 옮겨진 것뿐이다. 둘째, **2단원의 도구가 실제로 쓰이는 것을 눈으로 본다.** 함수·형 변환·예외 처리·조건문이 한 프로그램에서 한꺼번에 필요해진다.

수업에서는 2단원을 마친 뒤나 3단원 프로젝트의 산출물을 꾸밀 때 쓰면 알맞다.

<InfoBox variant="warn" label="먼저 확인할 것">
`tkinter`는 파이썬을 설치하면 대개 함께 들어온다. 따로 설치할 것이 없다. 다만 **브라우저에서는 창을 띄울 수 없다.** 이 부록의 예제는 전산실이나 집 컴퓨터에 설치된 파이썬에서 실행한다.

확인하는 방법은 파이썬을 열고 `import tkinter` 한 줄을 실행해 보는 것이다. 아무 말 없이 넘어가면 준비된 것이다.
</InfoBox>

<MoreBox tag="수업" title="교사용 메모 — 이 부록을 쓰는 자리">
- **시수**: 2차시면 1~4절과 온도 변환기까지 된다. 캔버스와 종합 프로젝트까지 하면 3~4차시다.
- **평가**: **채점 기준을 「예쁜가」가 아니라 「입력을 제대로 다루는가」에 둔다.** 1단원 5차시의 네 갈래 테스트를 채점표로 쓸 수 있다. 정식 차시가 아니므로 평가에 넣을 때는 `프그02-02`·`프그02-05`·`프그03-03`으로 진술하는 편이 안전하다.
- **환경**: 브라우저에서는 실행되지 않는다. 전산실에서 미리 `import tkinter` 한 줄을 확인해 둔다.
</MoreBox>

## 3. 이벤트 — 누를 때 비로소 실행된다

여기가 지금까지의 프로그램과 가장 다른 곳이다.

2단원까지의 프로그램은 **위에서 아래로 한 번 흐르고 끝났다.** GUI 프로그램은 `mainloop()`에 들어가면 아무것도 하지 않고 **기다린다.** 사람이 단추를 누르거나 글자를 치면 그때 정해 둔 함수가 불린다. 이렇게 일어나는 일 하나하나를 <Term ko="이벤트" en="event" desc="단추 누름·마우스 움직임·키 입력처럼 프로그램 밖에서 들어오는 사건" />라 한다.

<CodeSample lang="python" caption="단추를 누르면 라벨이 바뀐다" src="ex04_event.png" expect="" norun="창이 뜨는 예제다. 결과는 아래 그림으로 싣는다 — 단추를 한 번 누른 뒤의 모습이다.">
{`from tkinter import Tk, Label, Button

def 눌렀을때():
    라벨["text"] = "단추를 눌렀다"

창 = Tk()
창.title("이벤트")
창.geometry("300x130")

라벨 = Label(창, text="아직 누르지 않았다", font=("맑은 고딕", 12))
라벨.pack(pady=18)

단추 = Button(창, text="눌러 보기", command=눌렀을때)
단추.pack()

창.mainloop()`}
</CodeSample>

<InfoBox variant="warn" label="괄호를 붙이면 안 된다">
`command=눌렀을때` 에는 **괄호가 없다.** `command=눌렀을때()` 라고 적으면 창을 만드는 동안 함수가 한 번 실행되고, 그 **결과값**(여기서는 `None`)이 단추에 붙는다. 그러면 단추를 눌러도 아무 일도 일어나지 않는다.

2단원 14차시에서 「정의는 만들어 두는 것이고 호출은 실제로 쓰는 것」이라 했다. 여기서는 **호출하지 않고 함수 자체를 넘긴다.** 눌렀을 때 부르는 일은 tkinter가 한다.
</InfoBox>

<Cloze
  title="이벤트를 정리해 보자"
  text="단추에 할 일을 붙일 때는 [[command]] 옵션에 함수 이름을 적는다. 이때 함수 이름 뒤에 [[괄호|()::붙이면 만들 때 한 번 실행되고 끝난다]]를 붙이면 안 된다. 마우스 움직임처럼 단추가 아닌 사건을 받으려면 [[bind]]를 쓴다."
/>

### 단추가 아닌 사건 — bind()

마우스나 키보드처럼 단추가 아닌 사건은 `bind()`로 이어 준다.

```text
위젯.bind("<사건 이름>", 부를_함수)

<Button-1>     마우스 왼쪽 단추를 누름
<B1-Motion>    왼쪽 단추를 누른 채 움직임
<Key>          아무 키나 누름
<Return>       엔터 키
```

`bind()`로 이어 준 함수는 **인자를 하나 받는다.** 그 안에 사건에 관한 정보가 들어 있다. 마우스라면 `사건.x`, `사건.y`로 좌표를 알 수 있다. 5절의 그림판이 이것을 쓴다.

## 4. 입력을 받아 처리한다 — 온도 변환기

2단원 6차시에서 「입력받은 값은 언제나 문자열이다」라고 했다. **GUI에서도 똑같다.** `Entry`에서 꺼낸 값도 문자열이므로 계산하려면 숫자로 바꿔야 한다.

<CodeSample lang="python" caption="온도 변환기 — 화씨를 섭씨로" src="ex05_temp.png" expect="" norun="창이 뜨는 예제다. 결과는 아래 그림으로 싣는다 — 100을 넣고 단추를 누른 뒤의 모습이다.">
{`from tkinter import Tk, Label, Entry, Button

def 변환하기():
    try:
        화씨 = float(입력칸.get())
    except ValueError:
        결과라벨["text"] = "숫자를 넣어 주세요"
        return
    섭씨 = (화씨 - 32) * 5 / 9
    결과라벨["text"] = f"섭씨 {섭씨:.1f}도"

창 = Tk()
창.title("온도 변환기")

Label(창, text="화씨").grid(row=0, column=0, padx=8, pady=10)
입력칸 = Entry(창, width=10)
입력칸.grid(row=0, column=1, padx=8, pady=10)

단추 = Button(창, text="섭씨로 바꾸기", command=변환하기)
단추.grid(row=1, column=0, columnspan=2, pady=4)

결과라벨 = Label(창, text="결과가 여기 나온다", font=("맑은 고딕", 12))
결과라벨.grid(row=2, column=0, columnspan=2, pady=10)

창.mainloop()`}
</CodeSample>

## 6. 종합 — 숫자 맞히기를 창으로

1단원 6차시 생각 열기에 나온 숫자 맞히기를 GUI로 만든다. 3단원 3차시의 설계서 형식으로 먼저 겉모습을 정한다.

<CompareTable
  caption="만들 것을 먼저 적는다"
  headers={['정할 것', '이 프로그램에서는']}
  rows={[
    ['화면에 필요한 위젯', '안내 라벨 · 입력 칸 · 확인 단추 · 결과 라벨'],
    ['배치', '위에서 아래로 한 줄씩 → <code>pack()</code>'],
    ['받는 것', '1~100 사이의 정수 (문자열로 들어온다)'],

<CodeSample lang="python" caption="숫자 맞히기 — GUI 판" src="ex08_guess.png" expect="" norun="창이 뜨는 예제다. 아래 그림은 50을 넣고 확인을 한 번 누른 뒤의 모습이다.">
{`from tkinter import Tk, Label, Entry, Button
import random

정답 = random.randint(1, 100)
횟수 = 0

def 맞혀보기():
    global 횟수
    try:
        내답 = int(입력칸.get())
    except ValueError:
        결과라벨["text"] = "1부터 100까지의 수를 넣어 주세요"
        return
    횟수 += 1
    if 내답 < 정답:
        결과라벨["text"] = f"{내답} 보다 큽니다 ({횟수}번째)"
    elif 내답 > 정답:
        결과라벨["text"] = f"{내답} 보다 작습니다 ({횟수}번째)"
    else:
        결과라벨["text"] = f"맞혔습니다! {횟수}번에 성공"

창 = Tk()
창.title("숫자 맞히기")

Label(창, text="1~100 사이의 수를 맞혀 보자").pack(pady=8)

입력칸 = Entry(창, width=12)
입력칸.pack()

단추 = Button(창, text="확인", command=맞혀보기)
단추.pack(pady=6)

결과라벨 = Label(창, text="", font=("맑은 고딕", 12))
결과라벨.pack(pady=8)

창.mainloop()`}
</CodeSample>

<InfoBox variant="info" label="global 이 왜 필요한가">
`횟수 += 1` 한 줄 때문에 `global 횟수`가 필요하다. 2단원 15차시에서 「함수 안에서 만든 변수는 그 함수 안에서만 통한다」고 했다. 함수 안에서 밖의 변수를 **바꾸려** 하면 파이썬은 그것을 새 지역 변수로 보아 `UnboundLocalError`를 낸다.

`정답`은 읽기만 하므로 `global`이 필요 없다. **읽기는 되고 쓰기는 안 된다**는 것이 규칙이다.

값을 여러 곳에서 바꿔야 하는 프로그램이 커지면 이런 전역 변수가 헷갈리기 시작한다. 그때 쓰는 방법이 클래스인데, 이 부록의 범위를 넘는다.
</InfoBox>
