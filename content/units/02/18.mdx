## 생각 열기 — 껐다 켜도 남아 있으려면

17차시에서 파일에 쓰고 읽는 법을 배웠다. 그런데 `"w"` 모드는 열 때마다 내용을 지운다. 메모를 하나씩 쌓아 가려면 어떻게 할까.

<InfoBox variant="think" label="함께 생각해 보기">
메모를 쌓는 프로그램을 만들려면 **두 가지 일**이 필요하다. 새 메모를 남기는 일과, 지금까지 남긴 것을 불러오는 일이다. 이 둘을 16차시에서 배운 대로 나누면 함수가 몇 개 나올까? 그리고 각각 어느 파일 모드를 쓸까?
</InfoBox>

## 쌓아 가는 프로그램

<CodeSample lang="c" caption="간단 메모장 — 남기고 불러오기" expect={"1 오늘 변수를 배웠다\n2 내일은 반복문\n줄 수: 2\n"}>
{`#include <stdio.h>
#include <string.h>

void save(const char *text)
{
    FILE *f = fopen("diary.txt", "a");
    if (f == NULL) return;
    fprintf(f, "%s\\n", text);
    fclose(f);
}

int load_and_print(void)
{
    FILE *f = fopen("diary.txt", "r");
    if (f == NULL) return 0;

    char line[256];
    int no = 0;
    while (fgets(line, sizeof line, f) != NULL) {
        line[strcspn(line, "\\n")] = '\\0';
        printf("%d %s\\n", ++no, line);
    }
    fclose(f);
    return no;
}

int main(void)
{
    save("오늘 변수를 배웠다");
    save("내일은 반복문");
    int n = load_and_print();
    printf("줄 수: %d\\n", n);
    return 0;
}`}
</CodeSample>

## 두 함수의 겉모습

3단원 3차시의 다섯 칸으로 정리하면 이렇다.

| 함수 | 받는 것 | 돌려주는 것 | 하는 일 | 실패하면 |
|---|---|---|---|---|
| `저장` | 문자열 한 줄 | 없음 | 파일 끝에 한 줄 덧붙인다 | 열지 못하면 아무것도 하지 않는다 |
| `불러오기` | 없음 | 문자열 목록 | 파일 전체를 줄 목록으로 돌려준다 | 파일이 없으면 **빈 목록** |

**「실패하면」 칸이 이 프로그램의 핵심이다.** 처음 실행할 때는 파일이 아직 없다. 그때 오류로 멈추면 프로그램을 한 번도 쓸 수 없다.

<InfoBox variant="tip" label="파일이 없는 것은 오류가 아니다">
`불러오기` 가 파일이 없을 때 **빈 목록**을 돌려주는 것을 보자. "아직 아무것도 안 남겼다"는 상태를 빈 목록으로 나타낸 것이다. 오류를 내지 않으므로 부르는 쪽은 파일이 있는지 없는지 신경 쓰지 않아도 된다.

C의 `load_and_print` 도 `fopen` 이 실패하면 `0` 을 돌려준다. **같은 판단을 두 언어에서 각자의 방식으로 표현한 것**이다.
</InfoBox>

## 이어 쓰기가 만드는 차이

같은 프로그램을 두 번 실행하면 어떻게 될까.

| 실행 | `"a"` 모드 (지금) | `"w"` 모드였다면 |
|---|---|---|
| 1회 | 2줄 | 2줄 |
| 2회 | **4줄** | 2줄 (앞의 것이 지워짐) |
| 3회 | **6줄** | 2줄 |

`"a"` 는 앞의 것을 지키고 덧붙인다. **프로그램을 껐다 켜도 자료가 남는다**는 것이 이 모드에서 나온다.

<InfoBox variant="warn" label="실행기에서는 매번 새로 시작한다">
브라우저 실행기는 실행할 때마다 **깨끗한 상태에서 시작한다.** 그래서 [실행]을 여러 번 눌러도 줄 수가 늘지 않는다.

파일이 정말 쌓이는지 보려면 **전산실 파이썬에서 두 번 실행해** 보아야 한다. `diary.txt` 가 프로그램과 같은 폴더에 생기고 줄이 늘어나는 것을 눈으로 확인할 수 있다.

이것도 1단원 8차시에서 다룬 차이다 — **웹 기반 환경은 브라우저 밖으로 나가지 못한다.** 실행기 안의 파일은 그 실행 동안만 있는 임시 파일이다.
</InfoBox>

## 더 알아보기

<MoreBox tag="실무" title="지우기 전에 임시 파일에 쓴다">
활동 4단계의 「마지막 메모 지우기」에는 함정이 있다. 전부 읽어 목록을 만들고, `"w"` 로 열어 다시 쓰는 방식이다. **`"w"` 로 열는 순간 파일이 비워진다.** 그 뒤 쓰는 도중에 프로그램이 죽거나 전원이 꺼지면 자료를 통째로 잃는다.

실무에서 쓰는 방법은 이렇다. **임시 파일에 새 내용을 먼저 다 쓰고, 성공한 뒤에 원래 파일과 이름을 바꾼다.** 도중에 실패하면 원래 파일이 그대로 남아 있다. 이름을 바꾸는 일은 대개 한순간에 끝나므로 중간 상태가 남지 않는다.

문서 편집 프로그램이 저장할 때 실제로 이렇게 한다. **자료를 다루는 프로그램에서 「지우기 전에 안전한 사본」은 기본**이다.
</MoreBox>

<MoreBox tag="심화" title="파일이 곧 프로그램 사이의 다리">
17차시 「더 알아보기」에서 CSV를 봤다. 파일의 진짜 쓸모가 여기 있다 — **다른 프로그램과 자료를 주고받는 통로**다.

우리 프로그램이 성적을 CSV로 남기면 엑셀에서 열어 그래프를 그릴 수 있다. 반대로 엑셀에서 CSV로 내보낸 것을 우리 프로그램이 읽을 수도 있다. 두 프로그램은 서로를 전혀 모르고, **파일 형식만 약속되어 있으면** 된다.

3단원 3차시에서 부품끼리 주고받을 것을 못 박은 것과 같은 이야기다. 형식이 곧 약속이고, 그 약속이 지켜지면 안쪽은 서로 몰라도 된다.
</MoreBox>

<MoreBox tag="심화" title="여러 프로그램이 같은 파일을 만지면">
두 프로그램이 같은 파일에 동시에 쓰면 어떻게 될까. 내용이 섞이거나 한쪽이 쓴 것이 사라질 수 있다. 1단원 9차시에서 다룬 **덮어쓰기 문제**가 파일 수준에서 일어나는 것이다.

그래서 운영체제는 파일을 잠그는 장치를 제공하고, 여러 사람이 동시에 자료를 다뤄야 하는 곳에서는 파일 대신 데이터베이스를 쓴다. 데이터베이스는 이런 충돌을 다루는 것이 본업인 프로그램이다.

지금 단계에서는 **한 번에 한 프로그램만 그 파일을 만진다**고 전제하고 만들면 된다. 다만 그것이 전제라는 사실은 알아 두는 편이 좋다 — 3단원 2차시의 비기능 요구에 적어 둘 만한 내용이다.
