## 생각 열기 — 한 덩어리로 쓴 프로그램

성적 관리 프로그램을 지금까지 배운 것으로 쭉 이어 쓰면 이렇게 된다.

```text
개수 = int(input())
점수 = []
for _ in range(개수):
    점수.append(int(input()))
인원 = len(점수)
합계 = 0
for s in 점수:
    합계 += s
평균 = 합계 / 인원
최고 = max(점수)
최저 = min(점수)
print(f"인원 {인원}명")
print(f"평균 {평균:.1f}  최고 {최고}  최저 {최저}")
```

돌아간다. 그런데 3단원 3차시 생각 열기에서 본 문제가 그대로다 — **평균이 이상하게 나왔을 때 어디를 봐야 하는지** 알 수 없다.

<InfoBox variant="think" label="함께 생각해 보기">
이 코드를 세 덩어리로 나눈다면 어디를 자를까? 그리고 나눈 덩어리들이 **무엇을 주고받아야** 할까? 3단원 3차시에서 정한 부품 네 개와 견줘 보자.
</InfoBox>

## 3단원의 설계를 코드로

3단원 3차시에서 이 프로그램을 이렇게 나눴다.

| 부품 | 받는 것 | 돌려주는 것 | 하는 일 |
|---|---|---|---|
| `점수받기` | 없음 (사용자 입력) | 정수 목록 | 점수를 하나씩 받아 목록으로 |
| `통계내기` | 정수 목록 | 결과 묶음 | 인원·평균·최고·최저를 낸다 |
| `보여주기` | 결과 묶음 | 없음 (화면 출력) | 정해진 형식으로 찍는다 |

이제 그 설계를 코드로 옮긴다.

<CodeSample lang="python" caption="성적 관리 — 세 함수로 나눈 프로그램" stdin={"3\n88\n92\n75\n"} expect={"인원 3명\n평균 85.0  최고 92  최저 75\n"}>
{`def 점수받기():
    개수 = int(input())
    점수 = []
    for _ in range(개수):
        점수.append(int(input()))
    return 점수

def 통계내기(점수):
    return {
        "인원": len(점수),
        "평균": sum(점수) / len(점수),
        "최고": max(점수),
        "최저": min(점수),
    }

def 보여주기(결과):
    print(f"인원 {결과['인원']}명")
    print(f"평균 {결과['평균']:.1f}  최고 {결과['최고']}  최저 {결과['최저']}")

보여주기(통계내기(점수받기()))`}
</CodeSample>

<CodeSample lang="c" caption="성적 관리 — 세 함수로 나눈 프로그램" stdin={"3\n88\n92\n75\n"} expect={"인원 3명\n평균 85.0  최고 92  최저 75\n"}>
{`#include <stdio.h>

typedef struct { int n; double avg; int high; int low; } Stat;

int read_scores(int a[], int max)
{
    int n;
    if (scanf("%d", &n) != 1) return 0;
    if (n > max) n = max;
    for (int i = 0; i < n; i++) scanf("%d", &a[i]);
    return n;
}

Stat make_stat(const int a[], int n)
{
    Stat s = {n, 0, a[0], a[0]};
    int sum = 0;
    for (int i = 0; i < n; i++) {
        sum += a[i];
        if (a[i] > s.high) s.high = a[i];
        if (a[i] < s.low) s.low = a[i];
    }
    s.avg = (double)sum / n;
    return s;
}

void show(Stat s)
{
    printf("인원 %d명\\n", s.n);
    printf("평균 %.1f  최고 %d  최저 %d\\n", s.avg, s.high, s.low);
}

int main(void)
{
    int a[100];
    int n = read_scores(a, 100);
    if (n == 0) return 0;
    show(make_stat(a, n));
    return 0;
}`}
</CodeSample>

## 마지막 한 줄이 프로그램 전체다

Python 코드의 마지막 줄을 보자.

```text
보여주기(통계내기(점수받기()))
```

**받아서 → 계산해서 → 보여 준다.** 프로그램이 하는 일이 한 줄에 그대로 적혀 있다. 3단원 3차시 설계서의 「주 프로그램의 흐름」이 이것이었다.

안쪽부터 실행된다 — `점수받기()` 가 먼저 돌아 목록을 만들고, 그것이 `통계내기` 로 넘어가고, 결과가 `보여주기` 로 간다.

<InfoBox variant="tip" label="한 줄로 붙이는 것이 늘 좋은 것은 아니다">
중간 값에 이름을 붙여 나눠 적어도 된다.

```text
점수 = 점수받기()
결과 = 통계내기(점수)
보여주기(결과)
```

세 줄이지만 **중간에 무엇이 오가는지 이름으로 보인다.** 디버깅할 때도 중간 값을 찍어 보기 쉽다(3단원 6차시). 붙여 쓸지 나눠 쓸지는 읽기 쉬운 쪽으로 고른다 — 12차시에서 다룬 판단 기준이다.
</InfoBox>

## 어디서 자를지 정하는 기준

3단원 3차시의 기준을 그대로 쓴다.

  { tag: '기준 2', title: '이름으로 설명된다', body: '점수받기·통계내기·보여주기. 이름만 보고 하는 일이 짐작되면 잘 나뉜 것이다.' },
  { tag: '기준 3', title: '남의 속을 몰라도', body: '통계내기 는 점수가 어디서 왔는지 모른다. 목록만 받으면 된다.' },
  { tag: '기준 4', title: '두 곳 이상에서 쓰이면', body: '되풀이되는 계산은 따로 떼어 낸다.' },
]} />

여기에 하나를 더한다 — **입력·계산·출력을 섞지 않는다.** 14차시에서 계산 함수와 보여 주는 함수를 나눈 이야기가 프로그램 전체 수준에서도 통한다. 계산 함수가 화면을 건드리지 않으면 테스트할 수 있고, 다른 화면에도 붙일 수 있다.

<InfoBox variant="info" label="C의 read_scores 가 개수를 돌려주는 까닭">
Python의 `점수받기` 는 목록을 돌려준다. 목록이 스스로 길이를 알기 때문이다(4차시). C의 `read_scores` 는 **배열을 채우고 개수를 돌려준다.** 배열은 자기 길이를 모르므로 개수를 따로 알려 줘야 한다.

`max` 매개변수도 눈여겨보자. 배열의 크기를 넘겨 **그보다 많이 채우지 않게** 막는다. 4차시에서 배열 범위를 넘으면 C가 조용히 옆 메모리를 망가뜨린다고 했다. 함수를 만들 때 그 한계를 함께 받는 것이 관례다.
</InfoBox>

## 더 알아보기

<MoreBox tag="심화" title="파일을 여러 개로 나누기">
함수가 늘어나면 파일 하나가 길어진다. 그때는 파일을 나눈다. Python에서는 `성적계산.py` 를 따로 만들고 `import 성적계산` 으로 불러 쓴다. C에서는 `.c` 파일과, 함수 선언만 모은 `.h` 파일을 짝으로 만든다.

3단원 3차시에서 부품 목록을 만들었을 때 이미 파일 나누기의 밑그림이 그려진 셈이다. **설계서의 부품이 함수가 되고, 관련된 함수들이 모여 파일이 된다.** 나누는 기준은 같다 — 한 가지 일, 이름으로 설명, 남의 속을 몰라도.
</MoreBox>

<MoreBox tag="실무" title="main 은 얇게">
잘 나뉜 프로그램의 `main` 은 짧다. 실제 일은 함수들이 하고 `main` 은 **순서만 적는다.** 위 코드의 마지막 한 줄이 그 극단적인 예다.

`main` 이 길어지고 있다면 그 안에 이름 붙일 만한 일이 숨어 있다는 신호다. 반대로 `main` 만 읽고 프로그램이 무슨 일을 하는지 알 수 있다면 잘 나뉜 것이다. 남이 쓴 프로그램을 처음 읽을 때도 `main` 부터 보는 것이 요령이다.
</MoreBox>

<MoreBox tag="심화" title="가짜 부품으로 먼저 돌려 보기">
3단원 5차시와 이 차시 활동 2단계에서 껍데기를 먼저 만들었다. 이 방법이 협업에서 특히 힘을 낸다.

`통계내기` 가 아직 없어도 정해진 결과 묶음을 돌려주게 만들어 두면, `보여주기` 를 맡은 사람은 그것으로 출력 형식을 완성할 수 있다. 셋이 서로를 기다리지 않고 동시에 만드는 것이다.

다만 **진짜 부품이 완성되면 임시 코드를 반드시 지운다.** 남겨 두면 나중에 왜 이 값이 나오는지 아무도 모르게 된다. 3단원 6차시에서 확인용 출력문을 반드시 지우라고 한 것과 같은 이유다.
</MoreBox>
