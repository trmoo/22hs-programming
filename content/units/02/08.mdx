## 생각 열기 — 윤년인지 아닌지

윤년 규칙은 이렇다.

> 4로 나누어떨어지면 윤년이다. 다만 100으로 나누어떨어지면 윤년이 아니다. 그런데 400으로 나누어떨어지면 다시 윤년이다.

2024는 윤년, 2100은 아니고, 2000은 윤년이다.

<InfoBox variant="think" label="함께 생각해 보기">
이 규칙을 코드로 옮기려면 **세 조건을 어떻게 엮어야** 할까. "그리고"로 이어야 할 곳과 "또는"으로 이어야 할 곳이 어디인가? 7차시에서 배운 나머지 연산이 여기서 어떻게 쓰이는지도 함께 생각해 보자.
</InfoBox>

## 비교 연산자 — 결과는 참 또는 거짓

<Term ko="비교 연산자" en="comparison operator" desc="두 값을 견주어 참 또는 거짓을 돌려주는 연산자" />의 결과는 숫자가 아니라 **참이나 거짓**이다.

<CompareTable
  caption="비교 연산자 — 두 언어가 같다"
  headers={['하는 일', '기호', '보기', '결과']}
  rows={[
    ['같다', '<code>==</code>', '3 == 5', '거짓'],
    ['다르다', '<code>!=</code>', '3 != 5', '참'],
    ['크다', '<code>&gt;</code>', '5 &gt; 3', '참'],
    ['작다', '<code>&lt;</code>', '3 &lt; 5', '참'],
    ['크거나 같다', '<code>&gt;=</code>', '3 &gt;= 3', '참'],
    ['작거나 같다', '<code>&lt;=</code>', '3 &lt;= 3', '참'],
  ]}
/>

<InfoBox variant="warn" label="== 와 = 를 헷갈리지 않는다">
`=` 는 **넣기**, `==` 는 **견주기**다. 1차시에서 `=` 가 같다는 뜻이 아니라고 한 것이 여기서 갈린다.

Python에서 `if x = 5:` 라고 적으면 문법 오류로 바로 걸린다. 그런데 **C에서는 `if (x = 5)` 가 문법 오류가 아니다.** `x` 에 5를 넣고 그 값 5를 조건으로 쓴다. 5는 0이 아니므로 **늘 참**이 되어 조건이 아무 구실을 못 한다. 오류도 없이 조용히 잘못 도는 것이라 C에서 가장 찾기 어려운 실수 중 하나다.
</InfoBox>

<Term ko="논리 연산자" en="logical operator" desc="참·거짓을 엮어 새로운 참·거짓을 만드는 연산자" />는 조건 여러 개를 하나로 묶는다.

<CodeSample lang="python" caption="윤년 판별과 비교·논리 연산" expect={"2024 -> True\n2100 -> False\n2000 -> True\n2023 -> False\nTrue False True\nFalse True False\n"}>
{`for 해 in [2024, 2100, 2000, 2023]:
    윤년 = (해 % 4 == 0 and 해 % 100 != 0) or (해 % 400 == 0)

print(3 < 5, 3 == 5, 3 != 5)
print(True and False, True or False, not True)`}

<CodeSample lang="c" caption="윤년 판별과 비교·논리 연산" expect={"2024 -> 1\n2100 -> 0\n2000 -> 1\n2023 -> 0\n1 0 1\n0 1 0\n"}>
{`#include <stdio.h>

int main(void)
{
    int years[] = {2024, 2100, 2000, 2023};

    for (int i = 0; i < 4; i++) {
        int y = years[i];
        int leap = (y % 4 == 0 && y % 100 != 0) || (y % 400 == 0);
        printf("%d -> %d\\n", y, leap);
    }

    printf("%d %d %d\\n", 3 < 5, 3 == 5, 3 != 5);
    printf("%d %d %d\\n", 1 && 0, 1 || 0, !1);
    return 0;
}`}
</CodeSample>

### `True` 와 `1` — 결과를 적는 방식만 다르다

두 출력을 견줘 보자. Python은 `True`·`False` 로 찍고 C는 `1`·`0` 으로 찍는다. **판정 결과는 똑같다.** 2차시 「더 알아보기」에서 말한 대로 C에는 논리형이 원래 없어 0과 1로 나타낸다.

## 윤년 식을 뜯어 보기

```text
(해 % 4 == 0  and  해 % 100 != 0)  or  (해 % 400 == 0)
 └─── 4의 배수 ─┘    └── 100의 배수가 아니다 ──┘      └── 400의 배수 ──┘
 └──────────── 둘 다 참이어야 한다 ────────────┘
 └──────────────── 이쪽이거나 저쪽이면 윤년 ───────────────┘
```

| 해 | 4의 배수 | 100의 배수 아님 | and 결과 | 400의 배수 | 최종 |
|---|---|---|---|---|---|
| 2024 | 참 | 참 | 참 | 거짓 | **참** |
| 2100 | 참 | 거짓 | 거짓 | 거짓 | **거짓** |
| 2000 | 참 | 거짓 | 거짓 | 참 | **참** |
| 2023 | 거짓 | 참 | 거짓 | 거짓 | **거짓** |

**2000년이 핵심이다.** 앞의 `and` 는 거짓인데 뒤의 `or` 덕분에 참이 된다. 400의 배수라는 예외 규칙이 이 자리에서 살아난다.

<InfoBox variant="tip" label="괄호로 뜻을 못 박는다">
`and` 가 `or` 보다 먼저 계산되므로 위 식은 괄호 없이도 같은 뜻이 된다. 그래도 **괄호를 쓰는 편이 낫다.** 읽는 사람이 우선순위를 떠올리지 않아도 되고, 나중에 조건을 하나 더 붙일 때 어디에 넣어야 하는지 분명해진다. 7차시에서 한 이야기가 논리 연산에서 더 중요해진다.
</InfoBox>

/>

**마지막 줄이 3단원 7·8차시에서 실제로 겪은 그 잘못이다.** 부등호에 등호를 붙였는지가 경계값에서 갈리고, 경계값을 넣어 보지 않으면 끝까지 통과한다.

<InfoBox variant="info" label="Python은 0 < 점수 < 100 이 된다">
Python에서는 `0 < 점수 < 100` 이 사람이 읽는 그대로 동작한다. **C에서는 안 된다.** C는 `(0 < 점수) < 100` 으로 읽어, 앞의 결과 0이나 1을 100과 견주므로 늘 참이 된다. 같은 표기가 한 언어에서는 되고 다른 언어에서는 조용히 틀리는 자리라, 두 언어를 함께 배울 때 특히 조심할 곳이다.
</InfoBox>

## 더 알아보기

<MoreBox tag="심화" title="앞이 정해지면 뒤는 보지 않는다">
`a != 0 and 100 / a > 5` 라는 조건을 보자. `a` 가 0이면 뒤의 나눗셈에서 0으로 나누게 된다. 그런데 실제로는 오류가 나지 않는다. **`and` 는 앞이 거짓이면 뒤를 아예 계산하지 않기 때문이다.** `or` 도 앞이 참이면 뒤를 보지 않는다. 이것을 단축 평가라 한다.

이 성질을 알면 **안전 장치를 조건 순서로 만들 수 있다.** 위험한 계산 앞에 검사를 두면 되는 것이다. 반대로 뒤쪽 조건에 값을 바꾸는 일을 넣어 두면, 실행될 때도 있고 안 될 때도 있어 찾기 어려운 잘못이 된다. **조건식에는 값을 바꾸는 일을 넣지 않는다.**
</MoreBox>

<MoreBox tag="심화" title="실수를 == 로 견주지 않는다">
2차시에서 `0.1 + 0.2` 가 정확히 `0.3` 이 되지 않는다고 했다. 그래서 `if 합계 == 0.3:` 은 예상과 다르게 동작할 수 있다. 실수를 견줄 때는 **차이가 아주 작은지**를 본다.

```text
if abs(합계 - 0.3) < 0.000001:
```

"충분히 가까우면 같다고 보자"는 뜻이다. 얼마나 가까워야 같은 것으로 볼지는 다루는 값의 성질이 정한다 — 성적이라면 0.05, 과학 계산이라면 훨씬 작은 값을 쓴다. 3단원 2차시에서 "판정할 수 있게 적는다"고 한 것이 이런 자리에도 적용된다.
</MoreBox>

<MoreBox tag="실무" title="조건이 길어지면 이름을 붙인다">
윤년 식처럼 조건이 길어지면 한눈에 안 읽힌다. 이럴 때 **중간 결과에 이름을 붙이면** 읽기 쉬워진다.

```text
사년배수 = 해 % 4 == 0
백년배수 = 해 % 100 == 0
사백년배수 = 해 % 400 == 0
윤년 = (사년배수 and not 백년배수) or 사백년배수
```

줄 수는 늘었지만 마지막 줄이 규칙을 그대로 읽어 준다. 1차시에서 "좋은 이름이 주석을 줄인다"고 한 것이 조건식에도 그대로 적용된다. 조건이 셋을 넘어가면 이 방법을 검토할 만하다.
</MoreBox>
