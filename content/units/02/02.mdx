## 생각 열기 — 같은 기호, 다른 결과

두 줄을 견줘 보자.

```text
7 / 2
"7" + "2"
```

첫 줄은 3.5일 것 같다. 그런데 C에서는 3이 나온다. 둘째 줄은 9일 것 같지만 `"72"` 가 나온다.

<InfoBox variant="think" label="함께 생각해 보기">
`/` 와 `+` 는 같은 기호인데 왜 다르게 동작할까? 기호가 아니라 **양옆에 있는 값의 종류**가 결과를 정하기 때문이다. 그렇다면 프로그램에서 값의 종류에는 어떤 것들이 있을까?
</InfoBox>

## 자료형 — 값의 종류

## 나눗셈 — 자료형이 결과를 바꾸는 자리

<CodeSample lang="python" caption="Python의 나눗셈 세 가지" expect={"3.5\n3\n1\n<class 'float'>\n<class 'int'>\n72\n9\n"}>
{`print(7 / 2)
print(7 // 2)
print(7 % 2)
print(type(7 / 2))
print(type(7 // 2))
print("7" + "2")
print(int("7") + 2)`}
</CodeSample>

<CodeSample lang="c" caption="C의 나눗셈" expect={"3\n3.5\n1\n정수끼리 나누면 소수가 잘린다\n"}>
{`#include <stdio.h>

int main(void)
{
    int a = 7, b = 2;
    printf("%d\\n", a / b);
    printf("%.1f\\n", (double)a / b);
    printf("%d\\n", a % b);
    printf("정수끼리 나누면 소수가 잘린다\\n");
    return 0;
}`}
</CodeSample>

두 언어의 `/` 가 서로 다르게 동작한다.

<InfoBox variant="warn" label="C의 정수 나눗셈은 조용히 틀린다">
`int` 끼리 나누면 C는 소수 부분을 **버린다.** 오류도 경고도 없다. 419 ÷ 5 를 그대로 적으면 83.8이 아니라 83이 나온다. 3단원 5차시에서 평균을 구할 때 실제로 걸렸던 함정이 이것이다. 소수가 필요하면 `(double)` 로 한쪽을 실수로 바꿔야 한다.
</InfoBox>

## 문자열 `"7"` 과 정수 `7` 은 다르다

따옴표로 감싸면 숫자처럼 보여도 **글자**다. 그래서 `"7" + "2"` 는 더하기가 아니라 이어 붙이기가 되어 `"72"` 가 된다.

숫자로 계산하려면 자료형을 바꿔야 한다. 이것을 <Term ko="형 변환" en="type conversion" desc="값의 자료형을 다른 자료형으로 바꾸는 일" />이라 한다.

- Python: `int("7")` 은 문자열을 정수로, `str(7)` 은 정수를 문자열로, `float("3.5")` 는 실수로 바꾼다.
- C: `(double)a` 처럼 괄호 안에 자료형을 적어 바꾼다. 문자열 → 숫자는 `atoi`, `atof` 같은 함수를 쓴다.

**6차시에서 입력을 받을 때 이것이 곧바로 필요해진다.** 키보드로 들어온 값은 언제나 문자열이기 때문이다.

## 실수는 정확하지 않을 수 있다

<InfoBox variant="info" label="0.1 + 0.2 를 해 보면">
두 언어 모두 `0.1 + 0.2` 가 정확히 `0.3` 이 되지 않는다. 컴퓨터는 실수를 2진법으로 담는데, 0.1을 2진법으로 나타내면 끝없이 이어지기 때문이다. 10진법에서 1/3을 0.333…으로밖에 못 적는 것과 같은 사정이다.

그래서 **돈이나 성적처럼 정확해야 하는 값을 실수로 비교하지 않는다.** `if 합계 == 0.3:` 같은 조건은 예상과 다르게 동작할 수 있다. 8차시에서 비교 연산자를 다룰 때 다시 나온다.
</InfoBox>

## C는 크기를 미리 정한다

C에서 `int` 는 대개 4바이트다. 담을 수 있는 값의 범위가 정해져 있어, 그 범위를 넘으면 엉뚱한 값이 된다. Python의 정수는 자리 수 제한이 사실상 없어 큰 수도 그대로 담긴다.

## 더 알아보기

<MoreBox tag="심화" title="자료형은 왜 있는가">
"모든 값을 알아서 처리해 주면 편할 텐데 왜 종류를 나눌까." 두 가지 이유가 있다. 첫째는 **저장 공간**이다. 정수 88을 담는 데 4바이트면 충분한데 모든 값을 넉넉한 크기로 담으면 낭비가 크다. 둘째는 **연산의 뜻을 정하기 위해서**다. `+` 하나만 봐도 숫자끼리는 더하기, 글자끼리는 이어 붙이기다. 자료형이 없으면 무엇을 할지 정할 수 없다. `"7" + 2` 가 Python에서 오류가 나는 것도, 둘 중 무엇을 원하는지 언어가 짐작하지 않기로 했기 때문이다.
</MoreBox>

<MoreBox tag="실무" title="넘침 — 범위를 넘으면 값이 망가진다">
C의 `int` 가 4바이트라면 담을 수 있는 가장 큰 값은 약 21억이다. 여기에 1을 더하면 어떻게 될까. 오류가 나는 것이 아니라 **가장 작은 음수로 넘어간다.** 자동차 계기판이 한 바퀴 돌아 0이 되는 것과 비슷하다. 이것을 넘침(overflow)이라 한다. 큰 수를 다룰 때는 `long long` 같은 더 큰 자료형을 쓰거나, 애초에 그렇게 커질 수 있는지 따져 봐야 한다. Python은 이 걱정이 없는 대신 큰 수를 다룰 때 더 느리다.
</MoreBox>

<MoreBox tag="심화" title="C에는 참·거짓 자료형이 원래 없었다">
C는 오랫동안 논리형이 따로 없었다. **0이면 거짓, 0이 아니면 참**으로 다룬다. 그래서 8차시에서 볼 비교 결과가 `True` 가 아니라 `1` 로 찍힌다. 나중에 `<stdbool.h>` 를 포함하면 `bool`, `true`, `false` 를 쓸 수 있게 되었지만, 속은 여전히 정수다. 이 때문에 `if (x = 5)` 처럼 `==` 를 `=` 로 잘못 적어도 **문법 오류가 아니라 늘 참인 조건**이 되어 조용히 통과한다. C를 쓸 때 가장 자주 나는 실수 중 하나다.
</MoreBox>
