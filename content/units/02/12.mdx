## 생각 열기 — 숫자 맞히기를 만들려면

1단원 6차시에서 숫자 맞히기 놀이를 했다. 그것을 프로그램으로 만들어야 한다.

> 정답은 정해져 있다. 사용자가 수를 넣으면 「더 큰 수」·「더 작은 수」·「정답」을 알려 준다. 기회는 다섯 번이다.

<InfoBox variant="think" label="함께 생각해 보기">
이 문제에 필요한 것을 꼽아 보자. **몇 번 반복할지 미리 아는가?** 맞히면 다섯 번을 다 쓰지 않고 끝난다. 그렇다면 `for` 가 맞을까 `while` 이 맞을까? 그리고 「더 큰 수」와 「더 작은 수」를 가르는 것은 무엇인가?
</InfoBox>

## `for` 와 `while` 가르기

가장 자주 헷갈리는 자리다. 기준은 하나다.

> **반복을 시작할 때 몇 번 돌지 아는가?**

| 문제 | 아는가 | 고를 것 |
|---|---|---|
| 학생 30명의 점수를 더한다 | 안다 (30번) | `for` |
| 구구단 9단까지 찍는다 | 안다 (8 × 9) | `for` 중첩 |
| 정답을 맞힐 때까지 받는다 | 모른다 | `while` |
| 0을 넣을 때까지 값을 받는다 | 모른다 | `while` |
| 다섯 번 안에 맞히면 끝난다 | **최대 5번이지만 일찍 끝날 수 있다** | 둘 다 가능 |

마지막 줄이 숫자 맞히기다. 최대 횟수가 있으니 `for` 에 `break` 를 쓸 수도 있고, 남은 기회를 조건으로 두어 `while` 을 쓸 수도 있다.

<CodeSample lang="python" caption="숫자 맞히기 — 기회 다섯 번" stdin={"50\n90\n73\n"} expect={"50 더 큰 수\n90 더 작은 수\n73 정답\n"}>
{`정답 = 73
남은기회 = 5

while 남은기회 > 0:
    추측 = int(input())
    남은기회 -= 1
    if 추측 == 정답:
        print(추측, "정답")
        break
    elif 추측 < 정답:
        print(추측, "더 큰 수")
    else:
        print(추측, "더 작은 수")
else:
    print("기회를 다 썼다. 정답은", 정답)`}
</CodeSample>

<CodeSample lang="c" caption="숫자 맞히기 — 기회 다섯 번" stdin={"50\n90\n73\n"} expect={"50 더 큰 수\n90 더 작은 수\n73 정답\n"}>
{`#include <stdio.h>

int main(void)
{
    int answer = 73;
    int left = 5;
    int guess;
    int found = 0;

    while (left > 0) {
        if (scanf("%d", &guess) != 1) break;
        left--;
        if (guess == answer) {
            printf("%d 정답\\n", guess);
            found = 1;
            break;
        } else if (guess < answer) {
            printf("%d 더 큰 수\\n", guess);
        } else {
            printf("%d 더 작은 수\\n", guess);
        }
    }
    if (!found) printf("기회를 다 썼다. 정답은 %d\\n", answer);
    return 0;
}`}
</CodeSample>

### Python의 `while / else`

Python에는 반복에 `else` 를 붙일 수 있다. **`break` 로 끊기지 않고 조건이 거짓이 되어 정상으로 끝났을 때만** 실행된다. 그래서 "기회를 다 썼다"는 안내를 여기에 두면 딱 맞는다.

C에는 이 문법이 없다. 그래서 `found` 라는 표시 변수를 두고 반복 뒤에 검사한다.

<InfoBox variant="info" label="표시 변수를 쓰는 얼개">
`found` 처럼 **어떤 일이 일어났는지 기억해 두는 변수**는 자주 쓰인다. 반복 안에서 조건이 맞았는지를 밖에서 알아야 할 때 필요하다. 이름을 `found`·`찾았나` 처럼 참·거짓을 담는다는 것이 드러나게 짓는 것이 좋다(1차시).

Python에서도 `while / else` 를 모르면 표시 변수로 똑같이 만들 수 있다. **문법을 몰라도 얼개로 해결할 수 있다**는 것을 알아 두면 새 언어를 만나도 막히지 않는다.
</InfoBox>

## 더 알아보기

<MoreBox tag="심화" title="적어도 한 번은 실행해야 할 때">
`while` 은 조건을 **먼저** 검사하므로 처음부터 거짓이면 한 번도 안 돈다. 그런데 "일단 한 번은 물어보고, 계속할지 그다음에 정한다" 같은 경우가 있다. 메뉴를 보여 주고 선택을 받는 프로그램이 그렇다.

C에는 이런 경우를 위한 `do / while` 이 있다. 몸통을 먼저 실행하고 조건을 **나중에** 검사한다.

```text
do {
    메뉴를 보여 준다
    선택을 받는다
} while (선택 != 0);
```

Python에는 이 문법이 없어 `while True:` 로 돌리고 안에서 `break` 로 빠져나가는 얼개를 쓴다. **문법이 없으면 얼개로 만든다**는 이야기가 여기서도 통한다.
</MoreBox>

<MoreBox tag="실무" title="세 구조로 못 하는 일은 없다">
순차·선택·반복 세 가지만으로 **어떤 계산이든 표현할 수 있다**는 것이 알려져 있다. 프로그램의 흐름을 이 셋으로 짜는 방식을 구조적 프로그래밍이라 하고, 오늘날 대부분의 언어가 이 셋을 기본으로 갖추고 있다.

옛 언어에는 코드의 아무 줄로나 건너뛰는 문법이 있었다. 짧게 적을 수 있었지만, 흐름이 실타래처럼 엉켜 읽을 수 없는 코드가 되기 쉬웠다. 그래서 지금은 거의 쓰지 않는다. **읽을 수 있게 만드는 것이 짧게 만드는 것보다 중요하다**는 판단이 언어 설계 차원에서 내려진 셈이다.
</MoreBox>

<MoreBox tag="심화" title="무작위 수로 정답을 정하려면">
지금 코드는 정답이 `73` 으로 고정되어 있다. 실제 게임이라면 매번 달라야 한다. Python에서는 `import random` 뒤에 `random.randint(1, 100)` 을 쓴다.

이 교과서의 예제가 정답을 고정한 데는 이유가 있다. **실행할 때마다 결과가 달라지면 기대 출력과 대조할 수 없기 때문**이다. 3단원 7차시에서 테스트는 미리 정한 결과와 대조하는 일이라고 했다. 무작위가 들어간 프로그램을 테스트할 때는 무작위 부분을 떼어 내고 **값을 넘겨받는 형태로 만든다** — 16차시에서 함수로 나누는 것을 배우면 이 방법을 쓸 수 있다.
