## 생각 열기 — 값이 코드에 박혀 있으면

체질량지수를 구하는 프로그램을 이렇게 만들었다.

```text
키 = 170
몸무게 = 62
print(몸무게 / ((키/100) ** 2))
```

내 값은 나온다. 그런데 짝의 값을 보려면 **코드를 고쳐서 다시 실행**해야 한다. 반 전체가 쓰려면 서른 번 고쳐야 한다.

<InfoBox variant="think" label="함께 생각해 보기">
3단원 1차시에서 기획할 때 "누가 쓰는가"를 먼저 정했다. 만든 사람만 쓸 수 있는 프로그램과 **누구나 쓸 수 있는 프로그램**의 차이는 어디서 오는가? 그리고 값을 받아 오려면 프로그램이 무엇을 해야 할까?
</InfoBox>

## 표준 입력 — 키보드로 들어오는 값

<Term ko="표준 입력" en="standard input" desc="프로그램이 값을 받아들이는 기본 창구. 대개 키보드로 들어온다" />은 프로그램이 값을 받는 기본 창구다. 5차시의 표준 출력과 짝을 이룬다.

<CodeSample lang="python" caption="키와 몸무게를 받아 체질량지수 계산" stdin={"170\n62\n"} expect={"키(cm): 몸무게(kg): 체질량지수: 21.5\n"}>
{`키 = float(input("키(cm): "))
몸무게 = float(input("몸무게(kg): "))

미터 = 키 / 100
bmi = 몸무게 / (미터 * 미터)
print(f"체질량지수: {bmi:.1f}")`}
</CodeSample>

<CodeSample lang="c" caption="키와 몸무게를 받아 체질량지수 계산" stdin={"170\n62\n"} expect={"키(cm): 몸무게(kg): 체질량지수: 21.5\n"}>
{`#include <stdio.h>

int main(void)
{
    double cm, kg;
    printf("키(cm): ");
    scanf("%lf", &cm);
    printf("몸무게(kg): ");
    scanf("%lf", &kg);

    double m = cm / 100;
    printf("체질량지수: %.1f\\n", kg / (m * m));
    return 0;
}`}
</CodeSample>

<InfoBox variant="tip" label="이 실행기의 입력은 미리 적어 둔다">
위 예제의 **「입력」 칸**을 보자. `170` 과 `62` 가 미리 적혀 있다. 이 실행기는 `input()` 을 만났을 때 멈춰 서서 기다리지 않고, 그 칸에 적어 둔 값을 **한 줄씩 가져다 쓴다.**

칸의 값을 바꿔 [실행]을 다시 누르면 결과가 바뀐다. 짝의 키와 몸무게를 넣어 보자. 줄이 모자라면 그 자리에서 오류가 난다 — 받을 값이 몇 개인지 세어 그만큼 줄을 채운다.
</InfoBox>

## 안내 문구와 결과가 한 줄에 붙는 까닭

출력이 `키(cm): 몸무게(kg): 체질량지수: 21.5` 로 나왔다. 안내 문구 세 개가 붙어 버렸다.

`input("키(cm): ")` 의 안내 문구는 **줄바꿈 없이** 찍힌다. 사람이 직접 쓸 때는 그 뒤에 값을 타이핑하고 엔터를 치므로 줄이 바뀐다. 그런데 이 실행기는 입력을 미리 받아 두므로 타이핑하는 순간이 없어 줄이 안 바뀐다.

**이것은 프로그램의 잘못이 아니다.** 전산실에서 직접 타이핑해 보면 이렇게 나온다.

```text
키(cm): 170
몸무게(kg): 62
체질량지수: 21.5
```

## 들어온 값은 언제나 글자다

가장 중요한 것이다. 2차시에서 예고한 형 변환이 여기서 실제로 필요해진다.

<CompareTable
  caption="입력값을 숫자로 바꾸기"
  headers={['하려는 일', 'Python', 'C']}
  rows={[
    ['글자 그대로 받기', '<code>이름 = input()</code>', '<code>scanf("%s", name)</code>'],
    ['정수로 받기', '<code>n = int(input())</code>', '<code>scanf("%d", &n)</code>'],
    ['실수로 받기', '<code>x = float(input())</code>', '<code>scanf("%lf", &x)</code>'],
    ['형 변환 시점', '받은 <strong>뒤</strong> 사람이 바꾼다', '받으면서 <strong>형식 지정</strong>으로 정한다'],
  ]}
/>

<InfoBox variant="warn" label="형 변환을 빠뜨리면">
`키 = input("키(cm): ")` 라고만 적고 `키 / 100` 을 하면 Python은 이렇게 알려 준다.

```text
TypeError: unsupported operand type(s) for /: 'str' and 'int'
```

**글자를 숫자로 나눌 수는 없다**는 뜻이다. 2차시에서 `"7" + "2"` 가 `"72"` 가 된 것과 같은 사정이다. 입력을 받으면 **곧바로 형을 바꾸는 습관**을 들이는 편이 낫다.
</InfoBox>

### C의 `&` — 어디에 담을지 알려 준다

C의 `scanf("%lf", &cm)` 에 붙은 `&` 가 눈에 걸린다. Python의 `input()` 은 값을 **돌려주지만**, C의 `scanf` 는 **받은 값을 어디에 넣을지** 알려 줘야 한다. `&cm` 은 "cm 이라는 변수가 있는 자리"를 뜻한다.

3단원 5차시에서 C의 `average(scores, 5, &avg)` 가 결과를 `&avg` 에 채웠던 것과 같은 방식이다. **C에서 함수가 값을 바깥에 남기려면 이 방법을 쓴다.**

`&` 를 빠뜨리면 컴파일 경고가 나거나 프로그램이 엉뚱하게 동작한다. C에서 `scanf` 를 쓸 때 가장 자주 하는 실수다.

## 잘못된 입력을 어떻게 다룰까

사용자는 숫자 자리에 글자를 넣는다. 3단원 8차시에서 다른 모둠 프로그램을 깨뜨려 봤을 때 나온 그 문제다.

<CompareTable
  caption="숫자 자리에 글자가 들어오면"
  headers={['', 'Python', 'C']}
  rows={[
    ['무슨 일이 생기나', '<code>ValueError</code> 로 프로그램이 멈춘다', '<code>scanf</code> 가 값을 못 읽고 <strong>조용히 넘어간다</strong>'],
    ['드러나는가', '오류 메시지로 바로 드러난다', '드러나지 않는다. 변수에 쓰레기 값이 남는다'],
    ['어느 쪽이 위험한가', '—', '<strong>C</strong> — 잘못을 모른 채 계산이 이어진다'],
  ]}
/>

C에서는 `scanf` 가 **몇 개를 제대로 읽었는지 돌려준다.** 그것을 확인하면 잘못된 입력을 잡을 수 있다.

```text
if (scanf("%lf", &cm) != 1) {
    printf("숫자를 넣어야 한다\n");
    return 1;
}
```

3단원 3차시 설계서의 「실패하면」 칸에 적을 내용이 바로 이것이다. 12차시에서 조건문을 배운 뒤 이 검사를 제대로 붙여 볼 것이다.

## 더 알아보기

<MoreBox tag="심화" title="한 줄에 여러 값을 받기">
값을 하나씩 줄을 나눠 받는 것이 번거로울 때가 있다. `170 62` 처럼 한 줄에 두 값을 받으려면 Python에서는 받은 문자열을 쪼갠다.

```text
키, 몸무게 = input().split()
키 = float(키)
몸무게 = float(몸무게)
```

C의 `scanf("%lf %lf", &cm, &kg)` 는 한 번에 두 값을 읽는다 — 공백이나 줄바꿈을 알아서 건너뛰기 때문이다. **C의 `scanf` 는 이 점에서 편하고, 잘못된 입력을 다룰 때 불편하다.** 편한 쪽과 안전한 쪽이 갈리는 자리가 여기다.
</MoreBox>

<MoreBox tag="실무" title="입력을 믿지 않는 것이 기본이다">
3단원 8차시에서 다른 모둠 프로그램을 일부러 잘못 써 봤다. 실무에서는 그것이 훨씬 심하다. 프로그램을 쓰는 사람은 실수하고, 때로는 일부러 이상한 값을 넣는다. 그래서 **입력을 받는 곳이 프로그램의 문지기**가 된다. 3단원 4차시 「더 알아보기」에서 "잘못된 값은 들어오는 문 앞에서 막는 편이 낫다"고 한 이유다. 안쪽 함수들이 "여기 오는 값은 이미 정수다"라고 믿고 만들어질 수 있기 때문이다.
</MoreBox>

<MoreBox tag="심화" title="키보드가 아닌 곳에서 입력받기">
표준 입력이라는 이름에는 뜻이 있다. **키보드로 고정된 것이 아니라, 프로그램이 값을 받는 표준 창구**라는 말이다. 그래서 파일의 내용을 표준 입력으로 흘려 넣을 수도 있다. 명령 창에서 `python 프로그램.py < 값.txt` 라고 적으면 키보드 대신 파일에서 읽는다. 이 교과서의 예제 검사 도구도 같은 방식으로 동작한다 — 「입력」 칸의 내용을 표준 입력으로 넣어 실행하고 결과를 대조한다. **코드를 한 글자도 안 고치고 입력원을 바꿀 수 있다**는 것이 이 구조의 이점이다.
</MoreBox>
