## 생각 열기 — 숫자가 줄줄이 나오면

성적을 계산해 이렇게 찍었다.

```text
국어 88
영어 92.5
수학 75
평균 85.16666666666667
```

값은 다 맞다. 그런데 읽기가 불편하다. 숫자가 시작하는 자리가 들쭉날쭉하고, 평균은 소수점이 열네 자리나 나온다.

<InfoBox variant="think" label="함께 생각해 보기">
3단원 3차시에서 **출력 형식을 띄어쓰기까지 설계서에 적는다**고 했다. 왜 그렇게까지 해야 할까? 그리고 위 출력에서 무엇을 정해 주어야 보기 좋아질까? 두 가지를 꼽아 보자.
</InfoBox>

## 형식 지정 — 자리와 자릿수를 정한다

<Term ko="형식 지정" en="formatting" desc="값을 어떤 모양으로 문자열에 넣을지 정하는 일. 폭과 소수 자릿수, 정렬을 정한다" />은 값을 문자열에 끼워 넣을 때 모양을 정하는 일이다.

<CodeSample lang="python" caption="자리를 맞춘 성적표" expect={"국어    88.0\n영어    92.5\n수학    75.0\n평균    85.2\n"}>
{`과목 = ["국어", "영어", "수학"]
점수 = [88, 92.5, 75]

for i in range(3):
    print(f"{과목[i]}  {점수[i]:>6.1f}")
print(f"평균  {sum(점수) / 3:>6.1f}")`}
</CodeSample>

<CodeSample lang="c" caption="자리를 맞춘 성적표" expect={"국어    88.0\n영어    92.5\n수학    75.0\n평균    85.2\n"}>
{`#include <stdio.h>

int main(void)
{
    const char *subject[] = {"국어", "영어", "수학"};
    double score[] = {88.0, 92.5, 75.0};
    double sum = 0;

    for (int i = 0; i < 3; i++) {
        printf("%s  %6.1f\\n", subject[i], score[i]);
        sum += score[i];
    }
    printf("평균  %6.1f\\n", sum / 3);
    return 0;
}`}
</CodeSample>

두 언어의 출력이 **글자 하나까지 같다.** 형식을 정해 두면 언어가 달라도 같은 모양이 나온다는 것을 보여 주는 예다.

### `:>6.1f` 를 뜯어 보면

```text
{점수 :  >    6    .1    f}
       │  │    │     │    │
       │  │    │     │    └─ 실수로 (float)
       │  │    │     └────── 소수점 아래 한 자리
       │  │    └──────────── 전체 여섯 칸을 차지하게
       │  └───────────────── 오른쪽으로 붙여 (right)
       └──────────────────── 여기서부터 형식 지정
```

C의 `%6.1f` 도 같은 뜻이다. 숫자는 오른쪽 정렬이 기본이라 `>` 에 해당하는 표시가 없다.

<CompareTable
  caption="자주 쓰는 형식 지정"
  headers={['하려는 일', 'Python', 'C']}
  rows={[
    ['정수 그대로', '<code>{n}</code>', '<code>%d</code>'],
    ['실수 소수 한 자리', '<code>{x:.1f}</code>', '<code>%.1f</code>'],
    ['여섯 칸에 오른쪽 정렬', '<code>{x:>6}</code>', '<code>%6d</code> / <code>%6.1f</code>'],
    ['여섯 칸에 왼쪽 정렬', '<code>{x:&lt;6}</code>', '<code>%-6d</code>'],
    ['천 단위 쉼표', '<code>{n:,}</code>', '따로 없다. 직접 만들어야 한다'],
    ['문자열 그대로', '<code>{s}</code>', '<code>%s</code>'],
  ]}
/>

<InfoBox variant="tip" label="정렬 방향을 정하는 요령">
**숫자는 오른쪽, 글자는 왼쪽**이 기본이다. 숫자를 오른쪽에 붙이면 자릿수가 같은 자리에 모여 크기를 눈으로 견줄 수 있다. 위 예제에서 `88.0` 과 `92.5` 의 소수점이 한 줄로 맞아 있는 것을 보자. 왼쪽 정렬로 하면 소수점이 어긋나 읽기 어려워진다.
</InfoBox>

## 한글은 자리 맞춤이 언어마다 다르다

3차시에서 예고한 함정이 여기서 나온다. 위 예제는 과목 이름에 폭을 지정하지 **않았다.** 일부러 그렇게 했다.

- Python의 `f"{과목:<8}"` 은 **글자 수**로 여덟 칸을 센다. `국어` 는 2칸으로 세고 6칸을 채운다.
- C의 `%-8s` 는 **바이트 수**로 여덟 칸을 센다. `국어` 는 6바이트로 세고 2칸만 채운다.

같은 `8` 을 적어도 결과가 다르다. 그래서 이 교과서의 예제는 **한글에는 폭을 주지 않고 숫자에만 준다.**

<InfoBox variant="warn" label="한글 표를 자리 맞춰 찍고 싶다면">
방법은 두 가지다. 첫째, **한글 부분에는 폭을 주지 않고** 위 예제처럼 공백 두 칸으로 띄운다. 이름 길이가 같을 때만 맞는다. 둘째, **한글이 차지하는 칸 수를 직접 세어** 필요한 만큼 공백을 붙인다. 화면에서 한글은 대개 영문 두 칸 폭을 차지하므로, 글자 수 × 2 로 계산한다. 완벽한 해결은 아니지만 표를 읽을 수 있게는 만든다. 이 문제는 **한글을 쓰는 프로그램에서 계속 따라다닌다.**
</InfoBox>

## 줄바꿈을 다루는 법

`print` 는 끝에 줄바꿈을 자동으로 넣는다. 표를 만들 때는 그것을 막아야 한다.

<CompareTable
  caption="줄바꿈 다루기"
  headers={['하려는 일', 'Python', 'C']}
  rows={[
    ['찍고 줄바꿈', '<code>print(x)</code>', '<code>printf("%d\\\\n", x)</code>'],
    ['줄바꿈 없이 이어 찍기', '<code>print(x, end="")</code>', '<code>printf("%d", x)</code> — 원래 안 넣는다'],
    ['빈 줄 하나', '<code>print()</code>', '<code>printf("\\\\n")</code>'],
    ['값 사이에 넣을 것 정하기', '<code>print(a, b, sep=", ")</code>', '형식 문자열에 직접 적는다'],
  ]}
/>

**C는 줄바꿈을 자동으로 넣지 않는다.** `\n` 을 빠뜨리면 출력이 죄다 한 줄에 붙어 나온다. 반대로 Python은 넣는 것이 기본이라 막을 때 `end=""` 를 적는다. 11차시에서 별 찍기를 할 때 이 차이를 실제로 쓴다.

## 더 알아보기

<MoreBox tag="심화" title="반올림은 생각보다 까다롭다">
`{92.45:.1f}` 이 `92.5` 가 될지 `92.4` 가 될지는 짐작하기 어렵다. 2차시에서 다룬 대로 컴퓨터가 실수를 정확히 담지 못하기 때문이다. `92.45` 가 실제로는 `92.4499…` 로 담겨 있으면 내림이 된다. 성적처럼 민감한 값을 다룰 때는 **어떻게 반올림할지 요구 사항에 못 박고**(3단원 2차시), 경계값으로 테스트해야 한다(3단원 7차시). 정확한 반올림이 필요하면 실수 대신 정수로 계산하는 방법도 있다 — 소수 첫째 자리까지 필요하면 값을 10배 해서 정수로 다루는 식이다.
</MoreBox>

<MoreBox tag="실무" title="형식 문자열이 세 세대에 걸쳐 바뀌었다">
Python에서 문자열에 값을 끼워 넣는 방법은 여러 가지가 있다. 오래된 `"%d" % n` 방식, 그다음 `"{}".format(n)` 방식, 그리고 지금 주로 쓰는 `f"{n}"` 방식이다. 세 방식이 다 남아 있어 남의 코드를 읽을 때 섞여 나온다. **새로 쓸 때는 `f` 방식을 쓰는 것이 읽기 좋다** — 값이 들어갈 자리에 이름이 그대로 보이기 때문이다. C의 `printf` 는 오래됐지만 형식 표기가 거의 그대로 남아, Python의 `%` 방식이나 다른 언어에도 비슷하게 쓰인다. **하나를 익히면 여러 언어에서 통한다.**
</MoreBox>

<MoreBox tag="심화" title="화면에 바로 안 나올 때가 있다">
C에서 `printf` 로 찍었는데 화면에 바로 안 보이는 일이 있다. 출력을 한 글자씩 내보내면 느려서, 어느 정도 모아 두었다가 한꺼번에 내보내기 때문이다. 이것을 버퍼라 한다. 줄바꿈을 만나거나 버퍼가 차면 실제로 나간다. 그래서 프로그램이 중간에 비정상 종료하면 **찍었다고 생각한 출력이 안 나올 수 있다.** 디버깅할 때 이것 때문에 헷갈리는 일이 있으니, 마지막 출력이 안 보인다고 그 앞이 실행되지 않았다고 단정하지 않는 편이 좋다.
</MoreBox>
