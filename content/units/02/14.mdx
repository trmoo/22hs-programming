## 생각 열기 — 도형이 여러 개면

직사각형 넓이를 구해야 한다. 가로 4, 세로 5인 것과 가로 6, 세로 6인 것 둘 다.

13차시에서 함수가 필요하다는 것은 알았다. 그런데 **평균 함수는 목록 하나를 받았는데** 여기서는 가로와 세로 **둘**을 받아야 한다.

<InfoBox variant="think" label="함께 생각해 보기">
함수에 값을 여러 개 넘겨야 할 때 무엇을 정해야 할까. **몇 개를 받는지**와 **어느 것이 가로이고 어느 것이 세로인지**를 어떻게 약속할까? 3단원 3차시에서 부품의 「받는 것」 칸에 적었던 내용이 이 약속이다.
</InfoBox>

## 매개변수와 인수 — 같은 값의 두 이름

<Term ko="매개변수" en="parameter" desc="함수를 정의할 때 적는, 받을 값의 이름" />는 **정의할 때** 적는 이름이고, <Term ko="인수" en="argument" desc="함수를 부를 때 실제로 넘기는 값" />는 **부를 때** 넘기는 값이다.

```text
def 직사각형넓이(가로, 세로):      ← 가로, 세로가 매개변수
    return 가로 * 세로

직사각형넓이(4, 5)                 ← 4, 5가 인수
```

| | 매개변수 | 인수 |
|---|---|---|
| 언제 | 함수를 **정의**할 때 | 함수를 **부를** 때 |
| 무엇 | 받을 값에 붙인 **이름** | 실제로 넘기는 **값** |
| 위 예 | `가로`, `세로` | `4`, `5` |
| 몇 개 | 정의에서 정해진다 | **정의와 개수가 맞아야 한다** |

<InfoBox variant="tip" label="이름이 두 개인 까닭">
같은 값을 부르는 쪽과 받는 쪽이 **서로 다른 이름으로 부를 수 있어야** 하기 때문이다. 부르는 쪽에서 `가로길이` 라는 변수에 담아 두었어도, 함수 안에서는 `가로` 라는 이름으로 쓴다. 그래야 함수가 **누가 부르는지 모른 채** 만들어질 수 있다.

3단원 3차시에서 "남의 속을 몰라도 쓴다"고 했는데, 그 반대도 참이다 — **함수도 부르는 쪽의 속을 모른다.** 이 두 방향의 무관심이 부품을 나눠 만들 수 있게 해 준다.
</InfoBox>

## 순서가 뜻을 정한다

`직사각형넓이(4, 5)` 에서 4가 가로, 5가 세로다. **순서로 정해진다.** 넓이는 곱셈이라 바꿔도 결과가 같지만, 삼각형이라면 다르다.

```text
삼각형넓이(4, 5)   → 4 × 5 ÷ 2 = 10.0   (밑변 4, 높이 5)
삼각형넓이(5, 4)   → 5 × 4 ÷ 2 = 10.0   (여기서도 같지만)
```

나눗셈이 들어가면 순서가 답을 바꾼다.

```text
def 백분율(부분, 전체):
    return 부분 / 전체 * 100

백분율(30, 50)   → 60.0
백분율(50, 30)   → 166.7   ← 순서를 바꾸면 틀린다
```

<InfoBox variant="warn" label="순서 실수는 오류로 걸리지 않는다">
자료형이 같으면 순서를 바꿔 넘겨도 문법 오류가 나지 않는다. **답만 틀린다.** 3단원 6차시에서 「합칠 때 어긋나는 네 자리」 중 「값의 순서」를 든 것이 이 경우다.

막는 방법이 있다. Python에서는 **이름을 붙여 넘길 수 있다.**

```text
백분율(부분=30, 전체=50)
```

이렇게 적으면 순서가 바뀌어도 옳다. 매개변수가 셋을 넘어가면 이 방식이 훨씬 안전하다. C에는 이 문법이 없어 **순서를 문서에 적어 두는 것**으로 대신한다 — 3단원 3차시 설계서의 「받는 것」 칸이 그 자리다.
</InfoBox>

정의에서 둘을 받게 했으면 부를 때도 둘을 넘겨야 한다.

## 값을 안 돌려주는 함수

모든 함수가 값을 돌려주지는 않는다. 화면에 찍는 일만 하는 함수가 그렇다.

```text
def 표찍기(과목, 점수):
    print(f"{과목}  {점수:>6.1f}")
```

돌려줄 것이 없으므로 `return` 이 없다. C에서는 이런 함수를 `void` 로 적는다. 3단원 3차시 설계서에서 `report` 의 「돌려주는 것」 칸에 **「없음 (화면 출력)」** 이라고 적은 것이 이 경우다.

<InfoBox variant="info" label="계산하는 함수와 보여 주는 함수를 섞지 않는다">
평균을 구하면서 화면에도 찍는 함수를 만들면 편해 보인다. 그런데 그러면 **평균만 필요한 곳에서 쓸 수 없다.** 화면에 원치 않는 출력이 따라오기 때문이다. 테스트하기도 어려워진다(13차시 「더 알아보기」).

3단원 3차시에서 `summarize` 와 `report` 를 따로 둔 것이 이 판단이다. **계산은 값을 돌려주고, 보여 주는 일은 따로 맡긴다.** 16차시에서 이 원칙으로 프로그램을 나눈다.
</InfoBox>

## 더 알아보기

<MoreBox tag="심화" title="기본값을 정해 두기">
Python에서는 매개변수에 기본값을 줄 수 있다.

```text
def 평균(점수들, 자릿수=1):
    return round(sum(점수들) / len(점수들), 자릿수)

평균(점수)          → 자릿수는 1
평균(점수, 2)       → 자릿수는 2
```

자주 쓰는 값을 기본으로 두면 부르는 쪽이 짧아지고, 필요할 때만 바꿔 넘기면 된다. **기본값은 오른쪽 매개변수부터** 줄 수 있다 — 앞쪽에 기본값이 있고 뒤쪽에 없으면 순서로 짝을 지을 수 없기 때문이다. C에는 이 문법이 없어, 값을 다르게 받는 함수를 따로 만들거나 늘 전부 넘긴다.
</MoreBox>

<MoreBox tag="심화" title="값을 넘긴다는 것 — 사본인가 원본인가">
`직사각형넓이(가로길이, 세로길이)` 를 부를 때 함수 안에서 매개변수를 바꾸면 부르는 쪽의 변수도 바뀔까? **숫자라면 안 바뀐다.** 값의 사본이 넘어가기 때문이다.

그런데 Python에서 **리스트를 넘기면 사정이 다르다.** 1차시와 4차시 「더 알아보기」에서 다룬 이름표 이야기가 여기서 문제가 된다. 함수 안에서 `점수들.append(0)` 을 하면 부르는 쪽의 리스트도 바뀐다. 같은 리스트에 이름표가 하나 더 붙은 것이기 때문이다.

이것이 뜻하지 않은 변화를 만들 수 있어, **받은 값을 함수 안에서 바꾸지 않는 것**을 관례로 삼는다. 바꿔야 하면 사본을 만들어 쓰거나, 바꾼다는 사실을 함수 이름과 문서에 분명히 적는다.
</MoreBox>

<MoreBox tag="실무" title="매개변수가 많아지면 묶는다">
매개변수가 다섯 개를 넘어가면 부르는 쪽이 읽기 어려워진다. `만들기(1, 2, 3, 0, 1, 0)` 같은 코드는 무엇이 무엇인지 알 수 없다.

이럴 때 **관련된 값들을 묶어 하나로 넘긴다.** 3단원 3차시에서 통계 결과 다섯 항목을 묶음 하나로 돌려주기로 한 것과 같은 판단이다. Python은 사전으로, C는 구조체로 묶는다. 묶으면 항목이 늘어도 함수의 겉모습이 안 바뀌는 이점도 따라온다.

그리고 매개변수가 많다는 것 자체가 **그 함수가 여러 일을 하고 있다는 신호**일 때가 많다. 먼저 나눌 수 있는지 살펴보는 편이 좋다.
</MoreBox>
