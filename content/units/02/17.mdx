## 생각 열기 — 프로그램을 다시 켜면

16차시에서 만든 성적 관리 프로그램으로 점수를 서른 개 넣었다. 결과를 확인하고 프로그램을 닫았다.

다음 시간에 다시 열었더니 **아무것도 없다.** 서른 개를 처음부터 다시 넣어야 한다.

<InfoBox variant="think" label="함께 생각해 보기">
변수에 담은 값은 왜 사라질까? 1단원 8차시에서 다룬 **실행 환경**을 떠올려 보자. 프로그램이 돌아가는 동안 값은 어디에 있었는가? 그리고 그것을 프로그램이 끝난 뒤에도 남기려면 어디에 두어야 할까?
</InfoBox>

## 값이 사라지는 까닭

프로그램이 도는 동안 변수는 **메모리**에 있다. 메모리는 전기가 흐르는 동안만 값을 붙잡아 두는 장치이고, 프로그램이 끝나면 그 자리를 운영체제가 회수한다.

이 차시에서는 **텍스트 파일**만 다룬다. 눈으로 확인할 수 있어 배우기 좋고, 3단원 8차시에서 다룬 대로 **결과를 사람이 검증할 수 있기** 때문이다.

<InfoBox variant="info" label="숫자 88을 담는 두 방식">
텍스트 파일에 `88` 을 적으면 글자 `8` 과 `8` 로 **2바이트**가 들어간다. 이진 파일에 정수 88을 담으면 `int` 크기만큼, 대개 **4바이트**가 들어간다.

`123456789` 라면 텍스트는 9바이트, 이진은 여전히 4바이트다. **큰 수가 많으면 이진이 작고, 사람이 읽어야 하면 텍스트가 낫다.** 3차시에서 `"7"` 과 `7` 이 다르다고 한 이야기가 파일에서도 그대로 통한다.
</InfoBox>

<CodeSample lang="c" caption="파일에 쓰고 다시 읽기" expect={"파일 전체:\n첫째 줄\n둘째 줄\n1 첫째 줄\n2 둘째 줄\n"}>

#include <string.h>

int main(void)
{
    FILE *f = fopen("memo.txt", "w");
    if (f == NULL) { printf("파일을 열지 못했다\\n"); return 1; }
    fprintf(f, "첫째 줄\\n");
    fprintf(f, "둘째 줄\\n");

        printf("%d %s\\n", no++, line);

    fclose(f);
    return 0;

## 파일 모드 — 무엇을 할지 알려 준다

여는 목적을 <Term ko="파일 모드" en="file mode" desc="파일을 여는 목적. 읽기·쓰기·이어 쓰기 중 무엇인지 알려 준다" />로 알려 준다.

<CompareTable
  caption="파일 모드"
  headers={['모드', '뜻', '파일이 없으면', '파일이 있으면']}
  rows={[
    ['<code>"r"</code>', '읽기', '오류', '처음부터 읽는다'],
    ['<code>"w"</code>', '쓰기', '새로 만든다', '<strong>내용을 전부 지우고</strong> 처음부터 쓴다'],
    ['<code>"a"</code>', '이어 쓰기', '새로 만든다', '끝에 덧붙인다'],
  ]}
/>

<InfoBox variant="warn" label="쓰기 모드는 내용을 지운다">
`"w"` 로 열면 **기존 내용이 사라진다.** 되돌릴 수 없다. 값을 모아 두려는 파일을 실수로 `"w"` 로 열면 그동안 쌓은 것이 통째로 없어진다.

기존 내용을 지키면서 덧붙이려면 `"a"` 를 쓴다. 18차시에서 메모를 쌓아 갈 때 이 모드를 쓴다. **모드 한 글자가 자료를 지울지 살릴지 정한다.**
</InfoBox>

## 닫는 일을 빠뜨리지 않는 방법

Python의 `with open(...) as f:` 는 **블록이 끝나면 자동으로 닫아 준다.** 오류가 나서 중간에 빠져나가도 닫힌다. 그래서 Python에서는 이 방식만 쓰면 된다.

C에는 이런 장치가 없어 `fclose(f)` 를 직접 적어야 한다. 중간에 `return` 으로 빠져나가는 길이 있으면 그 앞에도 적어야 한다.

<CompareTable
  caption="파일을 다루는 문법 비교"
  headers={['하려는 일', 'Python', 'C']}
  rows={[
    ['열기', '<code>open(이름, 모드)</code>', '<code>fopen(이름, 모드)</code>'],
    ['열기 실패 확인', '오류가 발생한다', '<strong><code>NULL</code> 인지 반드시 확인</strong>'],
    ['한 줄 쓰기', '<code>f.write("글\\\\n")</code>', '<code>fprintf(f, "글\\\\n")</code>'],
    ['전체 읽기', '<code>f.read()</code>', '반복으로 한 줄씩 모은다'],
    ['한 줄씩 읽기', '<code>for 줄 in f:</code>', '<code>fgets(line, 크기, f)</code>'],
    ['닫기', '<code>with</code> 가 자동으로', '<code>fclose(f)</code>'],
  ]}
/>

<InfoBox variant="warn" label="C에서 열기 실패를 반드시 확인한다">
`fopen` 은 실패하면 `NULL` 을 돌려준다. 확인하지 않고 그 값으로 읽거나 쓰면 프로그램이 비정상 종료한다. 파일이 없을 때, 권한이 없을 때, 이름이 잘못됐을 때 모두 실패할 수 있다.

3단원 3차시 설계서의 「실패하면」 칸에 적을 내용이 정확히 이것이다. 파일을 다루는 함수는 **실패를 어떻게 알릴지 반드시 정해 두어야** 한다.
</InfoBox>

## 한글과 파일 이름

두 가지를 짚어 둔다.

- **파일 안의 한글** — Python은 `encoding="utf-8"` 을 적어 준다. 적지 않으면 컴퓨터마다 다른 방식으로 읽어 한글이 깨질 수 있다. 1단원 8차시에서 다룬 글자 설정 문제가 파일에서 가장 자주 나타난다.
- **파일 이름의 한글** — 위 예제의 파일 이름이 `memo.txt` 인 것에 이유가 있다. **Windows에서 C의 `fopen` 은 한글 파일 이름을 제대로 열지 못한다.** UTF-8로 적힌 이름을 다른 방식으로 해석하기 때문이다. 그래서 이 교과서의 C 예제는 파일 이름을 영문으로 쓴다.

<InfoBox variant="tip" label="이것이 비기능 요구다">
3단원 2차시에서 기능 요구와 비기능 요구를 나눴다. "파일을 읽어 보여 준다"는 기능 요구이고, **"한글이 깨지지 않는다"는 비기능 요구**다. 만드는 동안에는 문제를 일으키지 않다가 다른 컴퓨터에서 열었을 때 드러난다 — 3단원 8차시에서 시스템 테스트를 실제 쓸 컴퓨터에서 하라고 한 이유다.
</InfoBox>

## 더 알아보기

<MoreBox tag="심화" title="파일 위치를 어떻게 찾나">
`open("memo.txt")` 라고만 적으면 파일이 어디에 만들어질까. **프로그램이 실행된 폴더**다. 이것을 현재 작업 폴더라 한다. 그래서 같은 코드를 다른 폴더에서 실행하면 다른 곳에 파일이 생긴다.

정확한 위치를 정하려면 전체 경로를 적는다 — `open("D:/자료/memo.txt")`. 다만 그러면 다른 컴퓨터에서 안 돌아간다. 그래서 실무에서는 **프로그램 파일의 위치를 기준으로 경로를 만든다.** 이 문제는 학교 컴퓨터마다 폴더 구조가 달라 특히 자주 걸리므로, 파일이 안 열리면 "어느 폴더에서 실행했는가"를 먼저 확인해 볼 만하다.
</MoreBox>

<MoreBox tag="심화" title="줄바꿈 글자가 컴퓨터마다 다르다">
줄을 바꾸는 표시가 운영체제마다 다르다. Windows는 두 글자(`\r\n`), 리눅스와 macOS는 한 글자(`\n`)를 쓴다. 그래서 Windows에서 만든 텍스트 파일을 다른 곳에서 열면 줄 끝에 이상한 기호가 보이거나, 반대로 줄이 안 바뀌어 보일 수 있다.

Python은 파일을 텍스트 모드로 열면 이 차이를 알아서 맞춰 준다. C에서는 `fgets` 로 읽은 줄 끝에 `\r` 이 남을 수 있어, 위 예제처럼 줄바꿈을 잘라 내는 처리가 필요하다. 3단원 6차시에서 「합칠 때 어긋나는 자리」를 다뤘는데, **다른 운영체제와 파일을 주고받는 것도 그 어긋남이 생기는 자리**다.
</MoreBox>

<MoreBox tag="실무" title="쉼표로 나눈 표 — CSV">
표를 텍스트 파일에 담는 가장 흔한 방법이다. 한 줄이 한 행이고 칸을 쉼표로 나눈다.

```text
이름,국어,영어
학생1,88,92
학생2,70,80
```

확장자는 `.csv` 이고 엑셀에서도 열린다. 텍스트 파일이라 눈으로 확인할 수 있고, 3차시에서 배운 문자열 나누기로 읽을 수 있다. **프로그램과 표 계산 프로그램이 자료를 주고받는 다리** 구실을 해서 실무에서 아주 널리 쓰인다.

다만 값 안에 쉼표가 들어가면 칸이 어긋난다. 그때는 값을 따옴표로 감싸는 규칙을 쓴다 — 간단해 보이는 형식에도 정해 둘 것이 있다는 이야기다.
</MoreBox>
