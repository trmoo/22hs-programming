## 생각 열기 — 판단을 사람이 하고 있다

6차시 활동에서 체질량지수를 구했다. 그런데 그 값이 저체중인지 정상인지는 **표를 보고 사람이 판단**했다. 8차시에서 윤년 판별 조건식도 만들었지만 참·거짓을 찍어 보기만 했다.

<InfoBox variant="think" label="함께 생각해 보기">
프로그램이 스스로 판단하게 하려면 무엇이 더 있어야 할까. 8차시에서 만든 **참·거짓**과, 1단원 7차시 순서도의 **마름모**를 떠올려 보자. 그 마름모를 코드로 적으면 어떤 모양이 될까?
</InfoBox>

## 순차 구조 — 지금까지 쓴 것

<Term ko="순차 구조" en="sequence" desc="적힌 순서대로 위에서 아래로 한 번씩 실행되는 흐름" />는 적힌 대로 위에서 아래로 흐르는 것이다. 지금까지 쓴 모든 코드가 이것이었다.

1단원 7차시에서 그린 순서도로 보면 **네모와 화살표만 있고 마름모가 없는** 모양이다. 갈라지지 않으므로 어떤 값을 넣어도 지나가는 줄이 같다.

## 선택 구조 — 조건에 따라 갈라진다

<Term ko="선택 구조" en="selection" desc="조건의 참·거짓에 따라 서로 다른 줄을 실행하는 흐름" />는 마름모가 들어간 흐름이다. 조건이 참일 때와 거짓일 때 **서로 다른 줄**을 실행한다.

<InfoBox variant="warn" label="Python의 들여쓰기는 문법이다">
Python에서 `if` 아래 줄을 들여쓰지 않으면 **조건과 무관하게 늘 실행된다.** 반대로 C에서 들여쓰기만 하고 `{ }` 를 빠뜨리면, `if` 에 딸리는 것은 **바로 다음 한 줄뿐**이다. 그 아래 줄들은 조건과 무관하게 실행된다.

들여쓰기가 그럴듯해서 눈으로는 옳게 보이는데 동작이 다르다. **C에서는 몸통이 한 줄이어도 `{ }` 를 쓰는 편이 안전하다.**
</InfoBox>

## 다중 선택 — 등급 나누기

<CodeSample lang="python" caption="점수를 등급으로 바꾸기" expect={"95 -> A\n83 -> B\n71 -> C\n58 -> D\n"}>
{`for 점수 in [95, 83, 71, 58]:
    if 점수 >= 90:
        등급 = "A"
    elif 점수 >= 80:
        등급 = "B"
    elif 점수 >= 70:
        등급 = "C"
    else:
        등급 = "D"
    print(점수, "->", 등급)`}
</CodeSample>

<CodeSample lang="c" caption="점수를 등급으로 바꾸기" expect={"95 -> A\n83 -> B\n71 -> C\n58 -> D\n"}>
{`#include <stdio.h>

int main(void)
{
    int scores[] = {95, 83, 71, 58};

    for (int i = 0; i < 4; i++) {
        int s = scores[i];
        char grade;
        if (s >= 90)      grade = 'A';
        else if (s >= 80) grade = 'B';
        else if (s >= 70) grade = 'C';
        else              grade = 'D';
        printf("%d -> %c\\n", s, grade);
    }
    return 0;
}`}
</CodeSample>

### 순서가 중요하다

`83` 은 `>= 80` 도 참이고 `>= 70` 도 참이다. 그런데 B가 나온다. **`elif` 는 앞의 조건이 모두 거짓일 때만 검사하기 때문**이다. 위에서부터 처음 맞는 것에서 멈춘다.

그래서 **순서를 뒤집으면 틀린다.**

```text
if 점수 >= 70:      ← 95도 여기서 걸린다
    등급 = "C"
elif 점수 >= 80:    ← 여기까지 오지 않는다
    등급 = "B"
```

95점이 C가 된다. 큰 값부터 검사해야 한다.

<InfoBox variant="tip" label="if 를 여러 개 쓰는 것과 다르다">
`elif` 대신 `if` 를 네 번 쓰면 조건을 **전부** 검사한다. 95점이면 첫 조건에서 A가 되고, 그다음 `>= 80` 도 참이므로 B로 덮어써진다. 결국 D가 남는다.

**서로 배타적인 갈래에는 `elif` 를 쓴다.** 여러 조건이 동시에 참일 수 있고 각각 다른 일을 해야 할 때만 `if` 를 나열한다.
</InfoBox>

## 경계값을 어디에 두는가

`>= 90` 과 `> 90` 중 무엇을 쓸지가 **90점 한 명의 등급을 바꾼다.** 3단원 7·8차시에서 되풀이해 다룬 그 문제다.

| 조건 | 89점 | 90점 | 91점 |
|---|---|---|---|
| `점수 >= 90` | B | **A** | A |
| `점수 > 90` | B | **B** | A |

요구 사항에 "90점 이상 A"라고 적혀 있으면 `>=` 다. 3단원 2차시에서 "판정할 수 있게 적는다"고 한 것이 이 자리에서 코드로 갈린다.

## 중첩 조건 — 조건 안의 조건

조건 안에 또 조건을 넣을 수 있다.

```text
if 점수 >= 90:
    if 출석 >= 15:
        등급 = "A"
    else:
        등급 = "B"      ← 점수는 A인데 출석이 모자라 B
else:
    등급 = "C"
```

같은 판정을 `and` 로 적을 수도 있다.

```text
if 점수 >= 90 and 출석 >= 15:
    등급 = "A"
elif 점수 >= 90:
    등급 = "B"
else:
    등급 = "C"
```

<InfoBox variant="info" label="어느 쪽이 나은가">
정답은 없다. **중첩은 "점수를 먼저 보고 그다음 출석을 본다"는 순서가 드러나고**, `and` 는 조건이 나란히 보여 읽기 쉽다. 다만 중첩이 세 겹을 넘어가면 읽기 어려워지므로 그때는 `and` 로 펴거나, 13차시에서 배울 함수로 떼어 내는 것이 좋다. 1단원 5차시의 "한 곳에 한 가지 일"이 조건문에도 적용된다.
</InfoBox>

## 더 알아보기

<MoreBox tag="심화" title="값에 따라 갈라지는 다른 문법">
등급처럼 **범위**로 나눌 때는 `if / elif` 가 맞다. 그런데 "1번이면 이것, 2번이면 저것"처럼 **정해진 값 하나하나**로 갈라질 때는 다른 문법이 있다. C의 `switch` 문이다.

```text
switch (선택) {
    case 1: printf("추가\n"); break;
    case 2: printf("삭제\n"); break;
    default: printf("잘못된 선택\n");
}
```

`break` 를 빠뜨리면 아래 `case` 로 그대로 흘러 내려가는 것이 이 문법의 유명한 함정이다. Python에는 오래 이 문법이 없었고 `if / elif` 로 적어 왔다. 12차시에서 메뉴를 만들 때 어느 쪽이 읽기 좋은지 견줘 볼 만하다.
</MoreBox>

<MoreBox tag="심화" title="조건을 뒤집어 일찍 빠져나오기">
중첩이 깊어지는 것을 막는 방법이 있다. 조건을 뒤집어 **아닌 경우를 먼저 처리하고 빠져나오는** 것이다.

```text
if 점수 < 0 or 점수 > 100:
    print("잘못된 점수")
else:
    ... 긴 처리 ...
```

이것을 이렇게 바꾼다.

```text
if 점수 < 0 or 점수 > 100:
    print("잘못된 점수")
    끝낸다
... 긴 처리 ...   ← 들여쓰기가 한 단계 줄었다
```

잘못된 경우를 앞에서 걸러 내면 아래 코드는 "여기 오는 값은 옳다"고 믿고 쓸 수 있다. 6차시 「더 알아보기」의 "문지기"와 3단원 4차시의 "문 앞에서 막는다"가 같은 이야기다. 15차시에서 `return` 을 배우면 이 방법을 제대로 쓸 수 있다.
</MoreBox>

<MoreBox tag="실무" title="빠진 경우가 없는지 확인하는 습관">
`if / elif` 를 여러 개 적었을 때 **어느 조건에도 걸리지 않는 값**이 있는지 봐야 한다. 위 등급 코드는 `else` 가 있어 모든 값이 어딘가에 든다. 그런데 `else` 를 빼고 `elif 점수 >= 60:` 까지만 적으면, 59점은 등급이 정해지지 않아 `등급` 변수가 아예 만들어지지 않는다. Python에서는 그 뒤 `print(등급)` 에서 `NameError` 가 난다.

**`else` 를 습관적으로 붙이고 "여기 올 수 없다"고 생각되는 경우에도 무언가 적어 두는 것**이 안전하다. 1단원 6차시에서 알고리즘의 모든 경우에 출구가 있어야 한다고 한 것과 같은 원칙이다.
</MoreBox>
