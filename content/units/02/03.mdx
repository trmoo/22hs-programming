## 생각 열기 — 주민등록번호에서 생일만

`060315-3000000` 이라는 문자열이 있다. 여기서 생년월일 `060315` 만 꺼내려면 어떻게 해야 할까.

눈으로는 "앞에서 여섯 글자"라고 바로 말할 수 있다. 그런데 프로그램에게 시키려면 **몇 번째부터 몇 번째까지인지** 숫자로 말해 주어야 한다.

<InfoBox variant="think" label="함께 생각해 보기">
문자열의 첫 글자는 몇 번째일까? 사람은 "첫째"라고 하지만 프로그램은 대개 **0번째**부터 센다. 왜 0부터 셀까? 그리고 "앞에서 여섯 글자"를 0부터 세는 방식으로 말하면 어떻게 될까?
</InfoBox>

## 문자열은 글자가 순서대로 늘어선 것

<Term ko="문자열" en="string" desc="글자가 순서대로 늘어선 값" />은 글자를 순서대로 늘어놓은 값이다. 순서가 있으므로 **몇 번째 글자**를 가리킬 수 있다. 그 번호를 <Term ko="인덱스" en="index" desc="문자열이나 목록에서 몇 번째인지 가리키는 번호. 0부터 센다" />라 한다.

```text
 프  로  그  래  밍
 0   1   2   3   4      ← 앞에서 셀 때
-5  -4  -3  -2  -1      ← 뒤에서 셀 때 (Python)
```

<CodeSample lang="python" caption="글자 하나 꺼내기와 잘라 내기" expect={"길이: 5\n첫 글자: 프\n마지막 글자: 밍\n앞 세 글자: 프로그\n생년월일: 060315\n연도 앞자리 판단용 숫자: 3\n"}>
{`말 = "프로그래밍"
print("길이:", len(말))
print("첫 글자:", 말[0])
print("마지막 글자:", 말[-1])
print("앞 세 글자:", 말[0:3])

번호 = "060315-3000000"
print("생년월일:", 번호[0:6])
print("연도 앞자리 판단용 숫자:", 번호[7])`}
</CodeSample>

<CodeSample lang="c" caption="글자 하나 꺼내기와 잘라 내기" expect={"길이: 11\n첫 글자: p\n마지막 글자: g\n생년월일: 060315\n연도 앞자리 판단용 숫자: 3\n"}>
{`#include <stdio.h>
#include <string.h>

int main(void)
{
    char word[] = "programming";
    printf("길이: %zu\\n", strlen(word));
    printf("첫 글자: %c\\n", word[0]);
    printf("마지막 글자: %c\\n", word[strlen(word) - 1]);

    char id[] = "060315-3000000";
    char birth[7];
    strncpy(birth, id, 6);
    birth[6] = '\\0';
    printf("생년월일: %s\\n", birth);
    printf("연도 앞자리 판단용 숫자: %c\\n", id[7]);
    return 0;
}`}
</CodeSample>

## 슬라이싱 — 잘라 내기

Python의 `말[0:3]` 처럼 범위로 잘라 내는 것을 <Term ko="슬라이싱" en="slicing" desc="문자열이나 목록에서 정해진 범위만 잘라 내는 일" />이라 한다. 규칙 하나만 기억하면 된다.

> **시작 번호는 포함하고, 끝 번호는 포함하지 않는다.**

`[0:3]` 은 0, 1, 2번째 세 글자다. 3번째는 들어가지 않는다. 어색해 보이지만 이 규칙 덕분에 **끝 번호 − 시작 번호 = 개수**가 되어 계산이 쉬워진다. `[0:6]` 은 정확히 여섯 글자다.

<InfoBox variant="tip" label="0부터 세는 까닭">
1단원 6차시의 경계값 이야기와 이어진다. 0부터 세면 "몇 번째부터 몇 개"를 다루기 쉽다. 대부분의 프로그래밍 언어가 0부터 세므로, **"첫 글자는 0번"** 을 몸에 익히는 편이 낫다. 마지막 글자는 `길이 − 1` 번이다. 이 `−1` 을 빠뜨리는 것이 초보자가 가장 자주 하는 실수다.
</InfoBox>

## C의 문자열은 문자 배열이다

C에는 문자열 자료형이 따로 없다. **문자를 늘어놓은 배열**이 문자열 노릇을 한다. 그래서 두 가지가 따라온다.

    ['잘라 내기', '<code>말[0:6]</code>', '<code>strncpy</code> 로 옮기고 끝에 <code>\\0</code> 을 넣는다'],
    ['이어 붙이기', '<code>a + b</code>', '<code>strcat</code>'],
    ['끝을 아는 법', '길이를 스스로 안다', '<strong>널 문자 <code>\\0</code></strong> 이 나올 때까지'],
  ]}
/>

<Term ko="널 문자" en="null character" desc="C에서 문자열의 끝을 알리는 값 0. 글자로는 보이지 않는다" />는 C 문자열의 핵심이다. 배열 자체는 자기 길이를 모르므로, 어디까지가 문자열인지 표시가 필요하다. `strncpy` 로 여섯 글자를 옮긴 뒤 `birth[6] = '\0';` 을 적은 것이 그 표시다.

<InfoBox variant="warn" label="널 문자를 빠뜨리면">
`birth[6] = '\0';` 을 빼면 출력이 `060315` 에서 끝나지 않고 **메모리에 있던 쓰레기 값이 따라 나온다.** 오류가 나지 않고 실행되므로 더 위험하다. C에서 문자열을 손으로 만들 때는 널 문자를 넣었는지 늘 확인한다.
</InfoBox>

## 한글은 글자 수와 바이트 수가 다르다

위 두 예제의 결과를 견줘 보자. Python은 `"프로그래밍"` 의 길이를 **5**라고 했고, C는 `"programming"` 의 길이를 **11**이라고 했다. 영문이라 같아 보이지만, C에서 한글을 담으면 사정이 달라진다.

- Python의 `len("프로그래밍")` → **5** (글자 수)
- C의 `strlen("프로그래밍")` → **15** (UTF-8에서 한글 한 글자가 3바이트)

그래서 C 예제에서는 한글 대신 영문 단어를 썼다. C에서 한글을 글자 단위로 자르려면 바이트를 직접 세거나 별도 처리가 필요하다.

<InfoBox variant="info" label="5차시에서 또 만난다">
출력 자리를 맞출 때도 같은 문제가 나온다. Python은 글자 수로 폭을 세고 C는 바이트 수로 센다. **한글을 다루는 프로그램에서는 언제나 "글자 수인가 바이트 수인가"를 물어야 한다.**
</InfoBox>

## 더 알아보기

<MoreBox tag="심화" title="문자열은 바꿀 수 없다">
Python에서 `말[0] = "코"` 처럼 글자 하나만 바꾸려 하면 오류가 난다. 문자열은 한 번 만들면 **바꿀 수 없는 값**이기 때문이다. 바꾸려면 새 문자열을 만들어야 한다 — `말 = "코" + 말[1:]`. 처음에는 불편해 보이지만, 값이 조용히 바뀌지 않는다는 보장이 있어 프로그램을 이해하기 쉬워진다. 반대로 C의 문자 배열은 `word[0] = 'P';` 처럼 바로 바꿀 수 있다. **같은 "문자열"이라도 언어에 따라 성질이 다르다.**
</MoreBox>

<MoreBox tag="실무" title="자주 쓰는 문자열 기능">
이 차시에서는 자르기와 길이만 다뤘지만 실제로는 이런 것들을 더 쓴다. **찾기**(어디에 있는가), **바꾸기**(특정 글자를 다른 글자로), **나누기**(쉼표를 기준으로 여러 조각으로), **공백 없애기**(앞뒤의 빈칸 제거), **대소문자 바꾸기**. 입력받은 값을 검사할 때 특히 공백 없애기를 자주 쓴다 — 사용자가 실수로 앞에 빈칸을 넣는 일이 흔하기 때문이다. 필요할 때 찾아 쓰면 되고, **무엇을 찾아봐야 하는지 아는 것**이 지금 단계에서 더 중요하다.
</MoreBox>

<MoreBox tag="심화" title="글자를 숫자로 저장한다">
컴퓨터는 글자도 숫자로 저장한다. 영문 `A` 는 65, `a` 는 97이다. 이 약속을 아스키(ASCII) 코드라 한다. C에서 `word[0]` 이 `char` 형인 것은 그래서다 — 문자는 작은 정수인 셈이다. 그래서 C에서 `'a' - 'A'` 를 계산하면 32가 나오고, 이것으로 대소문자를 바꾸는 계산을 할 수 있다. 한글처럼 세계의 모든 글자를 담으려면 아스키로는 모자라, 유니코드라는 더 큰 약속을 쓴다. UTF-8은 유니코드를 바이트로 적는 방법 중 하나이며, 한글 한 글자가 3바이트가 되는 이유가 여기 있다.
</MoreBox>
