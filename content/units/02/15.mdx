## 생각 열기 — 같은 이름이 두 곳에 있으면

함수 안에서도 `개수` 라는 변수를 쓰고, 함수 밖에서도 `개수` 를 쓰고 있다.

```text
개수 = 0

def 세기():
    개수 = 100
    print("함수 안에서 개수 =", 개수)

세기()
print("함수 밖에서 개수 =", 개수)
```

<InfoBox variant="think" label="함께 생각해 보기">
마지막 줄은 `100` 일까 `0` 일까? 만약 함수 안에서 바꾼 것이 밖에도 영향을 준다면, **13차시에서 함수의 장점으로 든 「남의 속을 몰라도 쓴다」** 가 성립할까? 함수를 부를 때마다 내 변수가 바뀔지 걱정해야 한다면 어떻게 될까?
</InfoBox>

## 반환 — 계산한 값을 바깥으로

<Term ko="반환값" en="return value" desc="함수가 계산 결과로 바깥에 넘겨주는 값" />은 함수가 일을 마치고 내놓는 값이다. `return` 을 만나면 **그 자리에서 함수가 끝나고** 값이 부른 곳으로 돌아간다.

<CodeSample lang="python" caption="유효 범위와 반환값" expect={"함수 안에서 개수 = 100\n함수 밖에서 개수 = 0\n두배(7) = 14\n"}>
{`개수 = 0

def 세기():
    개수 = 100
    print("함수 안에서 개수 =", 개수)

세기()
print("함수 밖에서 개수 =", 개수)

def 두배(x):
    결과 = x * 2
    return 결과

print("두배(7) =", 두배(7))`}
</CodeSample>

<CodeSample lang="c" caption="유효 범위와 반환값" expect={"함수 안에서 count = 100\n함수 밖에서 count = 0\ntwice(7) = 14\n"}>
{`#include <stdio.h>

int count = 0;

void counting(void)
{
    int count = 100;
    printf("함수 안에서 count = %d\\n", count);
}

int twice(int x)
{
    int result = x * 2;
    return result;
}

int main(void)
{
    counting();
    printf("함수 밖에서 count = %d\\n", count);
    printf("twice(7) = %d\\n", twice(7));
    return 0;
}`}
</CodeSample>

**답은 `0` 이다.** 함수 안의 `개수` 와 밖의 `개수` 는 **이름만 같고 서로 다른 변수**다.

<InfoBox variant="tip" label="이 규칙이 함수를 안전하게 만든다">
지역 변수가 밖으로 새어 나가지 않으므로, **함수를 만드는 사람이 이름을 마음대로 지어도 된다.** `합계`, `i`, `결과` 같은 흔한 이름을 써도 부르는 쪽 변수를 망가뜨리지 않는다.

13차시에서 함수가 「안쪽 사정을 감춰 주는 벽」이라고 했다. 유효 범위가 그 벽을 실제로 세워 주는 장치다. 이것이 없으면 남이 만든 함수를 부를 때마다 **내 변수 이름과 겹치는지 확인**해야 한다.
</InfoBox>

## 전역 변수를 바꾸려면

함수 안에서 전역 변수를 **읽는 것**은 된다. 그런데 **바꾸려면** 별도 표시가 필요하다.

- Python: 함수 안에서 `global 개수` 라고 먼저 적어야 한다. 안 적고 `개수 = 100` 을 하면 새 지역 변수가 만들어진다 — 위 예제가 그 경우다.
- C: 지역에 같은 이름을 선언하지 않으면 그냥 전역이 바뀐다. 위 예제는 `int count = 100;` 으로 **지역을 새로 만들었기** 때문에 전역이 안 바뀌었다.

<InfoBox variant="warn" label="전역 변수는 되도록 쓰지 않는다">
전역 변수는 어디서나 바꿀 수 있어 편해 보인다. 그런데 그것이 문제다. **값이 틀렸을 때 누가 바꿨는지 찾을 수 없다.** 함수가 열 개면 열 곳을 다 봐야 한다.

3단원 6차시에서 어긋난 곳을 좁히는 방법을 다뤘다. 전역 변수는 그 좁히기를 어렵게 만든다. **필요한 값은 매개변수로 받고 결과는 반환값으로 돌려주는 것**이 원칙이다. 그러면 함수가 무엇에 영향을 주는지 겉모습만 보고 알 수 있다 — 3단원 3차시의 다섯 칸이 그 겉모습이다.
</InfoBox>

## `return` 은 그 자리에서 끝낸다

`return` 을 만나면 아래 줄은 실행되지 않는다. 이 성질을 쓰면 9차시 「더 알아보기」의 **일찍 빠져나오기**를 제대로 적을 수 있다.

```text
def 평균(점수들):
    if len(점수들) == 0:
        return None          ← 여기서 끝. 아래로 안 내려간다
    return sum(점수들) / len(점수들)
```

3단원 5차시에서 만든 그 코드다. 잘못된 경우를 먼저 걸러 내고 빠져나오면, **아래 코드는 「여기 오는 값은 옳다」고 믿고** 쓸 수 있다.

## 더 알아보기

<MoreBox tag="심화" title="여러 값을 한 번에 돌려주기">
Python은 값을 여러 개 돌려줄 수 있다.

```text
def 통계(점수들):
    return len(점수들), sum(점수들) / len(점수들), max(점수들)

인원, 평균, 최고 = 통계([88, 92, 75])
```

받는 쪽에서 이름을 나눠 받는다. 편하지만 **순서를 외워야 한다는 문제**가 있다 — 14차시의 순서 실수가 여기서도 생긴다. 항목이 셋을 넘으면 3단원 3차시처럼 **이름으로 꺼내는 묶음**으로 돌려주는 편이 안전하다.

C는 값을 하나만 돌려줄 수 있다. 그래서 구조체로 묶어 돌려주거나, 포인터로 채우는 방식을 쓴다. 3단원 6차시의 `Summary` 구조체가 앞의 방법이다.
</MoreBox>

<MoreBox tag="심화" title="함수가 자기를 부르면">
함수 안에서 자기 자신을 부를 수도 있다. 이것을 재귀라 한다.

```text
def 팩토리얼(n):
    if n <= 1:
        return 1
    return n * 팩토리얼(n - 1)
```

`팩토리얼(4)` 는 `4 × 팩토리얼(3)` 을 부르고, 그것이 다시 `3 × 팩토리얼(2)` 를 부른다. **`if n <= 1: return 1` 이 없으면 끝나지 않는다** — 1단원 6차시의 유한성이 여기서도 그대로 필요하다. 이렇게 멈추는 자리를 종료 조건이라 한다.

반복으로 할 수 있는 일은 대개 재귀로도 할 수 있고 그 반대도 그렇다. 어느 쪽이 읽기 쉬운지는 문제에 따라 다르다.
</MoreBox>

<MoreBox tag="실무" title="같은 입력에 같은 출력이면 다루기 쉽다">
매개변수로만 값을 받고 반환값으로만 결과를 내놓으며, 전역 변수를 건드리지 않고 화면에도 안 찍는 함수를 생각해 보자. 이런 함수는 **같은 값을 넣으면 언제나 같은 값이 나온다.**

이 성질이 있으면 좋은 점이 많다. 테스트가 쉽고(3단원 7차시), 순서를 바꿔 불러도 결과가 같고, 어디서 틀렸는지 좁히기 쉽다. 반대로 전역 변수를 읽거나 파일을 읽는 함수는 **부르는 시점에 따라 결과가 달라져** 같은 사례로 두 번 시험했을 때 다른 결과가 나올 수 있다.

프로그램에는 화면 출력이나 파일 읽기가 반드시 필요하다. 요령은 **그런 일을 하는 함수와 계산만 하는 함수를 나눠 두는 것**이다 — 14차시에서 계산과 출력을 섞지 않기로 한 판단이 여기까지 이어진다.
