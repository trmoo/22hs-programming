## 생각 열기 — 3725초는 몇 시간 몇 분 몇 초

`3725`초를 사람이 읽는 꼴로 바꿔야 한다. 손으로는 이렇게 한다.

> 3725를 3600으로 나누면 1시간, 남는 게 125초. 125를 60으로 나누면 2분, 남는 게 5초.

<InfoBox variant="think" label="함께 생각해 보기">
이 계산에 나온 두 가지 연산을 보자. **"나누면 몇 번"** 과 **"남는 게 얼마"** 다. 앞의 것은 나눗셈이지만 소수가 아니라 정수로 떨어져야 하고, 뒤의 것은 나눗셈의 나머지다. 2차시에서 본 `//` 와 `%` 가 바로 이것이다. 왜 이 둘이 짝으로 쓰이는지 생각해 보자.
</InfoBox>

## 몫과 나머지 — 자리를 나누는 도구

<CodeSample lang="python" caption="초를 시·분·초로 바꾸기" expect={"3725초 = 1시간 2분 5초\n복합 대입 결과: 30\n"}>
{`초 = 3725
시 = 초 // 3600
남은 = 초 % 3600
분 = 남은 // 60
나머지초 = 남은 % 60

print(f"{초}초 = {시}시간 {분}분 {나머지초}초")

n = 10
n += 5
n *= 2
print("복합 대입 결과:", n)`}
</CodeSample>

<CodeSample lang="c" caption="초를 시·분·초로 바꾸기" expect={"3725초 = 1시간 2분 5초\n복합 대입 결과: 30\n"}>
{`#include <stdio.h>

int main(void)
{
    int total = 3725;
    int h = total / 3600;
    int rest = total % 3600;
    int m = rest / 60;
    int s = rest % 60;

    printf("%d초 = %d시간 %d분 %d초\\n", total, h, m, s);

    int n = 10;
    n += 5;
    n *= 2;
    printf("복합 대입 결과: %d\\n", n);
    return 0;
}`}
</CodeSample>

### 왜 이 두 연산이 짝으로 쓰이나

`//` 는 **몇 묶음인지**, `%` 는 **묶고 남은 것**을 알려 준다. 그래서 큰 단위에서 작은 단위로 내려갈 때 늘 함께 쓰인다.

```text
3725초
  ├─ // 3600 → 1        (시간)
  └─  % 3600 → 125      (남은 초)
                 ├─ // 60 → 2   (분)
                 └─  % 60 → 5   (초)
```

같은 얼개가 여러 곳에 나온다.

<CompareTable
  caption="몫과 나머지가 쓰이는 곳"
  headers={['문제', '몫으로 얻는 것', '나머지로 얻는 것']}
  rows={[
    ['초 → 시·분·초', '큰 단위의 개수', '아래 단위로 넘길 값'],
    ['거스름돈 → 동전 개수', '500원 몇 개', '남은 금액'],
    ['쪽 나누기 — 100개를 10개씩', '몇 쪽', '마지막 쪽에 남는 개수'],
    ['짝수·홀수 판정', '—', '<code>n % 2</code> 가 0이면 짝수'],
    ['배수 판정', '—', '<code>n % 3</code> 이 0이면 3의 배수'],
  ]}
/>

**나머지로 배수를 판정하는 것**은 8차시의 윤년 판별에서 바로 쓴다.

<InfoBox variant="warn" label="음수에서는 두 언어가 다르다">
`-7 // 2` 와 `-7 % 2` 를 두 언어에서 해 보면 결과가 다르다.

| 식 | Python | C |
|---|---|---|
| 몫 | `-7 // 2` → **−4** | `-7 / 2` → **−3** |
| 나머지 | `-7 % 2` → **1** | `-7 % 2` → **−1** |

Python은 몫을 **내림**(작은 쪽으로), C는 **0 쪽으로** 버린다. 나머지의 부호도 따라 달라진다. 양수만 다룰 때는 차이가 없지만, 음수가 섞이면 **어느 언어로 옮기느냐에 따라 답이 바뀐다.** 3단원 5차시에서 "구현 중 설계와 달라진 것을 기록한다"고 한 것이 이런 경우다.
</InfoBox>

## 복합 대입 연산자

`n = n + 5` 는 자주 쓰는 꼴이라 짧게 적는 방법이 있다.

<CompareTable
  caption="복합 대입 연산자 — 두 언어가 같다"
  headers={['짧게', '같은 뜻', '보기']}
  rows={[
    ['<code>n += 5</code>', '<code>n = n + 5</code>', '10 → 15'],
    ['<code>n -= 5</code>', '<code>n = n - 5</code>', '10 → 5'],
    ['<code>n *= 2</code>', '<code>n = n * 2</code>', '15 → 30'],
    ['<code>n /= 2</code>', '<code>n = n / 2</code>', '30 → 15'],
    ['<code>n %= 3</code>', '<code>n = n % 3</code>', '10 → 1'],
  ]}
/>

1단원 7차시 순서도의 `합계 ← 합계 + i` 가 코드에서는 `합계 += i` 가 된다. 10차시에서 반복문으로 합계를 구할 때 계속 쓴다.

<InfoBox variant="tip" label="왜 짧게 적는 것이 나은가">
글자 수를 줄이려는 것이 아니다. `합계 = 합게 + i` 처럼 **왼쪽과 오른쪽에 같은 이름을 두 번 적다가 한쪽을 잘못 적는 실수**를 막아 준다. 이름을 한 번만 적으면 그 실수가 생길 자리가 없다.
</InfoBox>

## 우선순위 — 무엇을 먼저 계산하나

`2 + 3 * 4` 는 20이 아니라 14다. 수학과 같은 순서를 따른다.

1. 괄호 `()`
2. 거듭제곱 `**`
3. 곱하기 · 나누기 · 몫 · 나머지 (`*` `/` `//` `%`)
4. 더하기 · 빼기 (`+` `-`)

같은 순위끼리는 **왼쪽부터** 계산한다. `100 / 5 / 2` 는 `(100 / 5) / 2` 로 10이다.

<InfoBox variant="info" label="헷갈리면 괄호를 쓴다">
우선순위를 외워서 짧게 적는 것보다 **괄호로 뜻을 분명히 하는 편**이 낫다. 읽는 사람이 순위를 떠올리지 않아도 되기 때문이다. `(몸무게) / ((키/100) * (키/100))` 처럼 적으면 6차시의 체질량지수 식이 한눈에 읽힌다. 8차시에서 논리 연산자가 섞이면 이 원칙이 더 중요해진다.
</InfoBox>

## 더 알아보기

<MoreBox tag="심화" title="0으로 나누면">
`7 / 0` 을 하면 어떻게 될까. Python은 `ZeroDivisionError` 로 멈추며 무엇이 문제인지 알려 준다. C는 **정해진 동작이 없다** — 프로그램이 비정상 종료하거나, 환경에 따라 엉뚱한 값이 나올 수도 있다. 3단원 4차시에서 알고리즘을 적을 때 "나눗셈이 있는 곳마다 나누는 값이 0이 될 길을 막았는가"를 물으라고 한 것이 이 때문이다. 평균을 구하는 코드에서 인원이 0인 경우를 먼저 걸러 냈던 것도 같은 이유다.
</MoreBox>

<MoreBox tag="심화" title="1씩 늘리는 것만을 위한 연산자">
C에는 `n++` 와 `++n` 이라는 표기가 있다. 둘 다 `n` 을 1 늘리지만, **식 안에서 쓸 때 값을 언제 돌려주는지가 다르다.** `n++` 는 늘리기 전의 값을, `++n` 은 늘린 뒤의 값을 돌려준다. 4차시와 10차시의 `for` 문에서 `i++` 를 쓴 것이 이것이다. Python에는 이 표기가 없고 `n += 1` 만 쓴다 — 헷갈릴 자리를 아예 없앤 것이다. **문법이 적은 것이 손해만은 아니다.**
</MoreBox>

<MoreBox tag="실무" title="정수로 계산하면 정확하다">
5차시 「더 알아보기」에서 반올림이 까다롭다고 했다. 돈을 다룰 때 특히 문제가 된다. `0.1` 을 100번 더해도 정확히 `10.0` 이 되지 않기 때문이다. 그래서 실무에서는 **금액을 원 단위 정수로 다룬다.** 1,234원 56전을 다뤄야 하면 `123456` 전으로 담고, 화면에 찍을 때만 `// 100` 과 `% 100` 으로 나눠 `1234.56` 으로 만든다. 이 차시에서 배운 몫과 나머지가 그 자리에서 쓰인다. **자료를 어떤 모양으로 담을지가 정확도를 정한다** — 3단원 3차시의 이야기와 이어진다.
</MoreBox>
