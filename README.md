# 고등학교 「프로그래밍」 웹 교과서

2022 개정 교육과정 고등학교 **「프로그래밍」** 과목을 웹에서 읽고 실습하는 교과서다.
성취기준을 뼈대로 삼아 본문·예제·문항을 새로 집필했다.

- 배포 주소: https://trmoo.github.io/22hs-programming/
- 개발 규칙과 설계 결정: [CLAUDE.md](CLAUDE.md) · [docs/PLAN.md](docs/PLAN.md)

### 1단원 — 프로그래밍을 시작하기 전에

1. 프로그램과 프로그래밍 언어
2. 번역 방식으로 나눠 보는 언어 — 컴파일러와 인터프리터
3. 용도에 맞는 언어 고르기
4. 프로그램 개발 절차
5. 단계마다 조심할 것
6. 알고리즘이란 무엇인가
7. 순서도와 의사 코드로 표현하기
8. 개발 환경 준비하기
9. 함께 개발하기 — 공유와 협업
10. 1단원 마무리

### 3단원 — 쓸 만한 프로그램을 만들어 내기

아홉 차시가 **하나의 프로그램**을 기획에서 테스트까지 관통한다. 예시로 쓰는 「반 성적 정리 프로그램」은
1단원 5차시 생각 열기에 나왔던, 요구 사항이 어긋나 3주를 되돌린 그 프로그램이다. 이번에는 절차를 밟아 만든다.

1. 무엇을 만들지 정하기 — 기획과 요구 사항 도출
2. 요구 사항을 문서로 정리하기
3. 프로그램 구조를 설계하다
4. 설계한 프로그램의 알고리즘 작성
5. 설계를 코드로 옮기다
6. 나눠 만든 것을 합치다
7. 단위 테스트와 통합 테스트
8. 시스템 테스트와 고쳐 내기
9. 3단원 마무리

각 차시의 산출물이 다음 차시의 입력이 된다 — 명세서의 「확인 방법」 표가 7차시 테스트 사례가 되고,
설계서의 부품 목록이 5차시 파일 구조가 되며, 4차시 책상 검사에서 손으로 낸 값이 기대 결과가 된다.

## 학생용 — 이렇게 쓴다

1. **왼쪽 트리**에서 차시를 고른다. 오른쪽 목차로 문서 안을 오간다.
2. **상단의 Python / C 단추**로 예제 언어를 바꾼다. 고른 언어는 다음에 와도 유지된다.
3. **확인 문제**는 보기를 누르면 곧바로 채점되고 해설이 열린다. 점수는 저장되지 않는다.
4. **코드 작성 실습 칸에는 붙여넣기가 되지 않는다.** 직접 쳐 보라는 뜻이다.

### C 예제는 왜 실행 단추가 없나

브라우저에서 C를 실행해 주는 도구가 **한글을 제대로 출력하지 못해** 수업에 쓸 수 없다고 판단했다.
그래서 C 예제는 실제로 컴파일해 확인한 **기대 출력을 함께 싣고**, 코드 복사 단추로 가져가
전산실 컴파일러에서 돌리게 했다. 자세한 조사 근거는 [docs/PLAN.md](docs/PLAN.md) 결정 항목 6번에 있다.

## 교사용

- **성취기준 색인**(`/standards/`)에서 코드별로 어느 차시가 담당하는지 확인할 수 있다.
- **교과서 대조표**(`/crosswalk/`)로 "우리 학교 교과서의 이 단원이 여기 어디인가"를 찾는다.
  검정 교과서 6종의 단원명·절 제목·쪽수를 정리해 두었다.
- 차시마다 아래에 **「교과서에서 찾기」** 표가 있어 출판사별 위치가 바로 보인다.
- 학생 개인정보를 수집하지 않는다. 서버도 계정도 없고, 저장은 언어·출판사 선택 같은
  브라우저 안의 값(`localStorage`)까지다.

### 인쇄

차시 화면을 그대로 인쇄하면 좌우 패널과 실행 단추가 빠지고 본문만 나온다.
코드 작성 실습 칸은 빈 칸으로 인쇄되어 손으로 적을 수 있다.

## 개발

```bash
npm install
npm run dev      # http://localhost:4321
```

빌드는 **검사 6단계를 모두 통과해야** 산출물이 나온다.

```bash
npm run build
```

| 단계 | 검사 내용 |
|---|---|
| `check:data` | 성취기준 매핑·커버리지·`[확인필요]` |
| `check:content` | 본문 프런트매터 ↔ `curriculum.json` 이중 확인, 문항의 성취기준 매핑, 문체 |
| `check:toc` | 목차 강조 판정 단위 테스트 |
| `check:examples` | **예제 코드를 실제로 실행해 기대 출력과 대조** (Python·C) |
| `astro build` | 44페이지 정적 생성 |
| `check:html` | 중복 id·깨진 앵커·깨진 내부 링크·`lang`·`h1`·`alt` |

코드를 건드리지 않고 데이터·본문만 빠르게 검사하려면 `npm test`.

### 하위 경로 배포

GitHub Pages는 `/22hs-programming/` 아래에 올라간다. 빌드할 때 `BASE_PATH`를 준다.

```bash
BASE_PATH=/22hs-programming/ npm run build
```

본문에서 내부 링크를 절대 경로로 직접 적으면 이 배포에서 깨진다.
차시 링크는 `<LessonLink>`를 쓰고, `check:html`이 접두어가 빠진 링크를 잡는다.
