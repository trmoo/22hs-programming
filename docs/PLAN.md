- 작성일: 2026-08-04

## 0. 전제와 원칙

| 원칙 | 구체적 의미 |
|---|---|
| 성취기준이 유일한 뼈대 | 단원·차시 체계는 2022 개정 교육과정 「프로그래밍」 성취기준에서만 도출한다. 차시는 성취기준 코드에 **1:1 이상**으로 매핑되며, 매핑 없는 차시는 빌드/검사에서 실패로 처리한다 |
| 출판사 교과서는 길잡이일 뿐 | "우리 학교 교과서의 3단원이 이 사이트의 어디인가"를 찾게 해 주는 **대조표 + 라벨 전환**에만 쓴다. 목차 구조를 출판사에 맞추지 않는다 |
| 본문은 새로 쓴다 | 교과서 본문·삽화·평가문항을 전재하지 않는다. 설명은 성취기준과 성취기준 해설을 근거로 새로 집필한다 |
| 모르면 비워 둔다 | 확인되지 않은 단원명·차시 구성·성취기준 문구는 추측으로 채우지 않고 `[확인필요]`로 남긴다 |
| 학교 현장 우선 | 학교 전산실 크롬에서 동작하는 것이 최신 기술보다 중요하다. 오프라인·저사양·프록시 환경에서 **본문 학습은 절대 깨지지 않는다** |

### 현재 확인된 사실 / 미확인 사실

**확인됨 (로컬 파일 기준)**

- 프로젝트 폴더에 「프로그래밍」 검정 교과서 PDF 6종이 있다.
  - C 계열: `프로그래밍(C)(삼양미디어)`, `프로그래밍(C)(씨마스)`, `프로그래밍(C)(웅보출판사)`
  - Python 계열: `프로그래밍(Python)(성림출판)`, `프로그래밍(Python)(씨마스커뮤니케이션)`, `삼양미디어(Python)(삼양교육)`
- `삼양미디어(Python)(삼양교육)/교과서 PDF/`의 단원 구성은 **3단원**이다.
  `1단원 프로그래밍의 개요` / `2단원 프로그래밍의 기초` / `3단원 프로그램의 설계와 구현`

**미확인 — 전부 `[확인필요]`**

- 「프로그래밍」 성취기준 **코드 접두사**. `12프로`로 추정되지만 확인하지 못했다. 웹 검색으로 확정되지 않았고, 로컬 PDF는 이 환경에서 열 수 없다(PDF 렌더러 미설치).
- 성취기준의 **영역 구분과 개수, 각 성취기준 원문**.
- 나머지 5종 교과서의 단원명·차시 구성.

→ 확정 경로: 국가교육과정정보센터(NCIC) 「교육부 고시 제2022-33호 별책」 정보과 교육과정 원문, 또는 교사용 지도서 앞부속의 교육과정 연계표. **Phase 1의 첫 작업이다.**

## 1. 사이트맵

### 1-1. URL 규칙

```
/                              과목 홈 (단원 목록 · 성취기준 전체 지도 · 출판사 선택)
/units/{NN}/                   단원 열기   (NN = 01, 02, …)
/units/{NN}/{NN}/              차시 본문   (단원번호/차시번호)
/units/{NN}/review/            단원 마무리 (핵심 정리 · 단원평가 · 자가평가)
/standards/                    성취기준 색인 (코드 → 차시 역방향 링크)
/standards/{code}/             성취기준 1개 상세 (해설 · 담당 차시 · 관련 문항)
/crosswalk/                    출판사 대조표 (전체 표 형태)
/guide/                        이 사이트 사용법 (학생용 · 교사용)
```

참고 사이트와 달리 **한글 폴더명을 쓰지 않는다.** 퍼센트 인코딩된 URL은 복사·공유·검색 파라미터 처리에서 계속 문제를 만든다. 사람이 읽는 이름은 화면에 표시하고, URL은 번호로 고정한다.

### 1-2. 단원 구조

```
[확인필요] 성취기준 영역이 확정되기 전까지 단원 골격을 확정하지 않는다.

/units/01/  [확인필요] 1단원명
  ├─ /units/01/01/   [확인필요] 1차시 — 담당 성취기준 [확인필요]
  ├─ …
  └─ /units/01/review/

/units/02/  [확인필요]
/units/03/  [확인필요]
…
```

작업 가설(확정 아님): 삼양미디어(Python) 교과서가 3단원 체계인 점을 보면 교육과정 영역도 3개일 가능성이 있다. **그러나 이는 한 출판사의 편집 결과일 뿐 교육과정 영역과 같다는 근거가 없으므로 `[확인필요]`로 둔다.**

### 1-3. 언어 모드 (Python / C)

언어는 **URL을 분기하지 않는다.** 한 차시 안에서 코드 블록만 모드에 따라 바뀐다.

- 전역 상태 `lang ∈ {python, c}` → `localStorage["prog-lang"]`
- 페이지 상단 고정 토글로 전환, 전환 시 본문 내 모든 코드 블록이 동시에 바뀜
- 코드 블록이 한쪽 언어만 있으면 "이 예제는 Python으로만 제공됩니다" 안내를 노출하고 감추지 않는다

이유: 같은 차시에 두 URL을 두면 성취기준 매핑이 두 배로 늘고 링크 공유가 깨진다.

## 2. 데이터 모델

콘텐츠와 구조를 분리한다. **구조·매핑·대조표는 JSON, 본문은 문서 파일**이다. 검색·필터·매핑 검증은 전부 JSON만 보고 동작한다.

### 2-1. `data/curriculum.json` — 교육과정 원본

성취기준 원문을 담는 **단일 진실 공급원**. 사람이 손으로 채우고, 채운 근거를 함께 적는다.

```jsonc
{
  "subject": {
    "name": "프로그래밍",
    "schoolLevel": "고등학교",
    "category": "진로 선택",           // [확인필요]
    "codePrefix": "[확인필요]",         // 예: "12프로" — NCIC 고시 원문으로 확정
    "credits": null,                   // [확인필요] 학점/시수
    "source": {
      "document": "[확인필요] 교육부 고시 제2022-33호 별책 O 정보과 교육과정",
      "verifiedAt": null,              // 확인한 날짜. null이면 미확인 = [확인필요]
      "url": null
    }
  },
  "domains": [
    {
      "id": "D1",
      "no": 1,
      "name": "[확인필요]",
      "standards": ["[확인필요]"]
    }
  ],
  "standards": [
    {
      "code": "[확인필요]",            // 예: "12프로01-01"
      "domainId": "D1",
      "text": "[확인필요]",             // 성취기준 원문 (그대로 인용 — 법령 문서)
      "commentary": "[확인필요]",       // 성취기준 해설 (있는 경우)
      "considerations": "[확인필요]",   // 교수·학습/평가 시 고려 사항
      "keywords": [],
      "verified": false
    }
  ]
}
```

> 성취기준 **원문은 그대로 인용한다**(교육과정 고시는 공공 문서이며, 코드와 문구가 정확해야 교사가 신뢰할 수 있다). 전재 금지 대상은 **출판사 교과서의 본문·삽화·문항**이다. 둘을 혼동하지 않는다.

### 2-2. `data/units.json` — 단원·차시 구조와 매핑

```jsonc
{
  "units": [
    {
      "id": "U01",
      "no": 1,
      "slug": "01",
      "title": "[확인필요]",
      "summary": "[확인필요]",
      "bigIdeas": [],                  // 단원 열기의 '핵심 아이디어' 2~3개
      "standards": ["[확인필요]"],      // 이 단원이 담당하는 성취기준 전체
      "lessons": [
        {
          "id": "U01L01",
          "no": 1,
          "slug": "01",
          "title": "[확인필요]",
          "hook": "[확인필요]",          // 히어로 lead 문장
          "standards": ["[확인필요]"],   // ★ 최소 1개 필수 — 비면 빌드 실패
          "objectives": [],             // "…한다" 형태 학습 목표 3개 내외
          "keywords": [],
          "estimatedMinutes": 50,
          "langs": ["python", "c"],     // 이 차시가 제공하는 코드 언어
          "activities": [],             // { type, title } — 실습/시뮬레이터/토의
          "status": "draft"             // draft | review | published
        }
      ],
      "review": { "quizCount": null, "selfAssessKey": "prog-u01" }
    }
  ]
}
```

**불변 조건(빌드 시 검사)**

1. 모든 `lesson.standards[]`의 코드가 `curriculum.json`에 존재한다.
2. `curriculum.json`의 모든 성취기준이 **최소 한 차시에서 담당된다** (미담당 = 커버리지 구멍 → 경고).
3. `lesson.standards[]`가 빈 배열이면 **에러**.
4. `unit.standards[]`는 소속 차시들의 `standards` 합집합과 일치한다.

### 2-3. `data/publishers.json` — 출판사 대조표

```jsonc
{
  "publishers": [
    {
      "id": "samyang-py",
      "label": "삼양미디어(Python)",
      "language": "python",
      "verified": true,                 // 실제 교과서에서 확인했는가
      "source": "삼양미디어(Python)(삼양교육)/교과서 PDF/ 단원별 파일명",
      "units": [
        { "no": 1, "title": "프로그래밍의 개요" },
        { "no": 2, "title": "프로그래밍의 기초" },
        { "no": 3, "title": "프로그램의 설계와 구현" }
      ]
    },
    { "id": "cmass-c",  "label": "씨마스(C)",              "language": "c",      "verified": false, "units": [] },
    { "id": "samyang-c","label": "삼양미디어(C)",          "language": "c",      "verified": false, "units": [] },
    { "id": "ungbo-c",  "label": "웅보출판사(C)",          "language": "c",      "verified": false, "units": [] },
    { "id": "sungrim-py","label": "성림출판(Python)",      "language": "python", "verified": false, "units": [] },
    { "id": "cmasscom-py","label": "씨마스커뮤니케이션(Python)","language": "python","verified": false, "units": [] }
  ],
  "crosswalk": [
    {
      "lessonId": "U01L01",
      "map": {
        "samyang-py": { "unitNo": 1, "unitTitle": "프로그래밍의 개요", "sectionTitle": "[확인필요]", "pages": null }
      }
    }
  ]
}
```

**라벨 전환 동작**: 출판사를 선택하면 좌측 트리와 본문 상단의 단원 라벨이
`1단원 [우리 단원명]` → `1단원 [우리 단원명]  ·  삼양미디어 «프로그래밍의 개요»`
형태로 **병기**된다. 우리 단원명을 지우고 대체하지 않는다 — 사이트의 뼈대는 성취기준이라는 원칙을 화면에서도 유지한다. 매핑이 없으면 `대조 정보 없음 [확인필요]`을 그대로 노출한다.

### 2-4. 본문 콘텐츠

`content/units/{NN}/{NN}.{md|html}` — 한 차시 = 한 파일. 프런트매터로 `units.json`과 이중 확인한다.

```yaml
---
lessonId: U01L01
standards: ["[확인필요]"]     # units.json과 불일치하면 빌드 실패
title: "[확인필요]"
status: draft
---
```

### 2-5. 코드 블록 데이터

본문에 인라인으로 쓰되, 언어 전환을 위해 **쌍으로 묶는다.**

```html
<div class="coderun" data-run data-caption="첫 프로그램">
  <pre data-lang="python">print("안녕하세요")</pre>
  <pre data-lang="c">#include &lt;stdio.h&gt;
int main(void) { printf("안녕하세요\n"); return 0; }</pre>
</div>
```

- `data-lang`이 현재 모드와 맞는 블록만 표시
- 실행 결과가 언어별로 달라야 할 경우 `data-expect`로 기대 출력을 적어 두고 검사 스크립트가 회귀 확인

### 2-6. 문항 데이터

```jsonc
{

  "lessonId": "U01L01",
```

## 4. 기술 스택 후보와 트레이드오프

### A안 — 무빌드 정적 HTML + 바닐라 JS + JSON

참고 사이트(wonedu.org)와 같은 방식. `data/*.json`을 JS로 읽어 트리·검색·필터를 그린다.

### B안 — Astro + Markdown 콘텐츠 + JSON 데이터

`content/`의 Markdown과 `data/*.json`을 빌드 시 결합해 정적 HTML을 생성한다. 인터랙션만 아일랜드로 붙인다.

| 기준 | A안 (무빌드) | B안 (Astro) |
|---|---|---|
| 첫 페이지 만들기 | ◎ 즉시 | △ 툴체인 세팅 필요 |
| 차시 40개까지 유지비 | ✕ 헤더·트리·목차를 파일마다 복제 → 디자인 1회 변경에 전 파일 수정 | ◎ 템플릿 1곳 수정 |
| 3단 레이아웃·우측 목차 자동 생성 | △ 런타임 JS로 매번 생성 | ◎ 빌드 시 생성, JS 없이도 표시 |
| 성취기준 검색·필터 | ○ 가능(JSON + JS) | ◎ 색인을 빌드 시 생성 |
| 매핑 불변 조건 검증 | ✕ 자동화 지점이 없음 (별도 스크립트를 손으로 돌림) | ◎ **빌드 실패로 강제** — 이 프로젝트의 핵심 원칙을 기계가 지킴 |
| 출판사 라벨 전환 | ○ 런타임 치환 | ◎ 데이터 주입 + 런타임 전환 |
| `[확인필요]` 추적 | △ grep | ◎ 빌드 리포트로 집계 |
| 학교 전산실 크롬 동작 | ◎ | ◎ (결과물은 같은 정적 HTML) |
| `file://` · USB 배포 | ◎ 그대로 동작 | △ 상대 경로 설정 + 데이터 인라인 필요 (가능하지만 손이 감) |
| 교사가 직접 수정 | ◎ HTML 열어서 고침 | ○ Markdown은 더 쉽지만 배포는 빌드 필요 |
| Pyodide/C wasm 통합 | ◎ 스크립트 태그 | ◎ 동일 |
| 인쇄·접근성 | ○ | ○ |
| 의존성·수명 위험 | ◎ 거의 없음 | △ Node·Astro 메이저 업그레이드 부담 |
| 필요 역량 | HTML/CSS/JS | + Node 툴체인, 빌드 개념 |

**추천: B안.** 결정 근거는 요구사항의 절반(좌측 트리, 우측 목차, 성취기준 검색·필터, 출판사 라벨 전환, 1:1 매핑 보장)이 **데이터 기반 기능**이라는 점이다. A안에서는 이것들을 전부 런타임 JS로 만들고 일관성은 사람이 지켜야 한다. 특히 "모든 차시는 성취기준에 매핑된다"는 원칙은 **빌드가 실패해 줘야 지켜지는 종류의 규칙**이고, A안에는 그 강제 지점이 없다.

**B안을 택할 때 반드시 함께 정할 것**: `build.format: 'file'` + 상대 경로로 출력하고, 검색 색인을 `fetch` 대신 **JS 파일로 인라인**한다. 그러면 `file://`에서도 열린다(요구사항이라면).

**A안이 더 맞는 경우**: 배포처에 Node를 쓸 수 없다 / 다른 교사가 HTML을 직접 고쳐 쓰는 것이 중요하다 / 총 차시가 15개 이하로 작다.
